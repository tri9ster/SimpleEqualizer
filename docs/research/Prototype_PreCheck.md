# 試作の前の確認(2026-10-12)

試作を始める前に確かめるべきことの一覧と、その結果。
Claude がコマンドで読み取れるものは確認した。音を鳴らす操作と、設定を変える操作はしていない。

## 1. 結果のまとめ

- 開発環境は、1点を除いて準備できている。残りは Xcode の初回セットアップ(利用者の作業)。
- アプリの前提(光デジタル出力には音量調整の機能がない)は、実機で確認できた。
- 仕様書 3.3 の「24 ビット出力に対応しているか」は、対応していると確認できた。
- 案A の API は開発キットに入っている。この Mac で実際に動くかは、試作しないと分からない。
- いまの macOS の出力先は「Mac miniのスピーカー」で、USB SPDIF Adapter ではない。試作を試す前に切り替えが要る。

## 2. 確認したこと

### 2.1 開発環境

| 確認すること | 結果 | 状態 |
| --- | --- | --- |
| コマンドのビルドが Xcode 本体を向いているか | `xcode-select -p` が Xcode 本体を返した | 済み |
| Xcode と開発キットの版 | Xcode 27.0、macOS 27.0 の開発キット | 済み |
| Xcode のライセンスに同意しているか | 同意済み(`xcodebuild -license check` が 0 で終了) | 済み |
| Xcode の初回セットアップが終わっているか | 終わっていない(`xcodebuild -checkFirstLaunchStatus` が 69 で終了) | **要対応** |
| 署名に使える証明書があるか | 「Apple Development」の証明書が1つある | 済み |
| Xcode に Apple のアカウントが登録されているか | 設定からは読み取れなかった | 未確認 |

### 2.2 案A の API

| 確認すること | 結果 | 状態 |
| --- | --- | --- |
| `AudioHardwareCreateProcessTap` が開発キットにあるか | ある。macOS 14.2 以降で使える | 済み |
| 元の音を消す設定(`muteBehavior`)があるか | ある(`CATapMuted`、`CATapMutedWhenTapped`) | 済み |
| この Mac と USB SPDIF Adapter で実際に動くか | 試作で確かめる | 未確認 |

### 2.3 出力装置(USB SPDIF Adapter)

| 確認すること | 結果 | 状態 |
| --- | --- | --- |
| 音量調整の機能があるか | ない。全体・左・右のどれにもない | 済み |
| 消音の機能があるか | ある | 済み |
| 24 ビット出力に対応しているか | 対応している。いまも 48 kHz / 24 ビット / 2ch で動いている | 済み |
| 対応している形式 | 44.1 / 48 / 96 / 192 kHz、それぞれ 16 ビットと 24 ビット | 済み |
| 圧縮された信号の形式があるか | ある(48 kHz の AC-3。Dolby Digital をそのまま通す形式) | 済み |
| 装置が申告している遅れ | 遅延 50 フレーム、安全余裕 50 フレーム、バッファ 512 フレーム | 済み |
| いまの macOS の出力先 | 「Mac miniのスピーカー」。USB SPDIF Adapter は通知音の出力先にだけなっている | 済み |

補足:

- 音量調整の機能がないのは、同じ Mac につながっているディスプレイ(DELL S2722QC)も同じだった。
  「Mac miniのスピーカー」には音量調整がある。
- バッファ 512 フレームは、48 kHz では約 11 ミリ秒にあたる。これは出力側だけの値で、
  アプリ全体の遅れは、取り出し側と加工の分が加わる。全体の値は試作で測る。

## 3. 試作しないと分からないこと

- 案A の API が、macOS 27 と USB SPDIF Adapter の組み合わせで音を取り出せるか。
- 「システム音声の録音」の許可ダイアログが出て、許可したあとに取り出しが始まるか。
- 元の音が消え、加工した音だけが出るか(二重に聞こえないか)。
- 音の遅れが、動画の視聴で気にならない範囲か。
- アプリが異常終了したとき、音が元の経路に戻るか(無音のままにならないか)。
- 再生するアプリが 44.1 kHz と 48 kHz を切り替えたときに、音切れや雑音が出ないか。
- スリープから復帰したあとも、音が出続けるか。

## 4. Claude には確認できないこと

- macOS の許可(システム音声の録音、アクセシビリティ)の現在の状態。
- SONOS Ray 側の設定(本体の音量、ラウドネス、低音・高音)。
- 音の聞こえ方のすべて。

## 5. 試作の前に利用者が行うこと

1. Xcode の初回セットアップを終わらせる(管理者パスワードが要る)。

   ```bash
   sudo xcodebuild -runFirstLaunch
   ```

2. 試す直前に、macOS の出力先を「USB SPDIF Adapter」に切り替える。
3. 試す直前に、SONOS Ray 側の音量を下げておく(不具合があると最大音量で音が出るため)。

## 6. 確認の方法

- 開発環境と API: `xcode-select`、`xcodebuild`、`security find-identity`、開発キットのヘッダーの検索。
- 出力装置: Core Audio の情報を読み取るだけの Swift スクリプト(音は鳴らさず、設定も変えない)。
  スクリプトは一時的な場所で実行し、プロジェクトには残していない。
