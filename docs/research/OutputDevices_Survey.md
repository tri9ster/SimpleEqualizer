# 出力先まわりの調査(2026-10-14)

段階5 の TICKET-001。いまの出力先を加工する(TICKET-003)を作る前に、装置の見分け方と、切り替えのときに何が起きるかを調べた。

## 1. この Mac の出力先(Claude が調べた)

装置の情報を読むだけのスクリプト(`tools/list-output-devices.swift`)で調べた。音は出していない。設定も変えていない。

| 出力先 | つなぎ方 | サンプリング周波数 | 出力のストリーム | 形式 | 装置の音量 | 装置の消音 |
| --- | --- | --- | --- | --- | --- | --- |
| USB SPDIF Adapter | USB | 48000 Hz | 1 本(入力 0 本) | 2ch / 32 ビット 浮動小数点 / 交互 | **なし** | あり・変えられる |
| Mac miniのスピーカー | 内蔵 | **96000 Hz** | 1 本(入力 0 本) | 2ch / 32 ビット 浮動小数点 / 交互 | **あり・変えられる** | あり・変えられる |
| DELL S2722QC(ディスプレイのスピーカー) | DisplayPort | 48000 Hz | 1 本(入力 0 本) | 2ch / 32 ビット 浮動小数点 / 交互 | **なし** | なし |

分かったこと:

- **3つとも、形は同じである**(出力 1 本、入力 0 本、2ch、32 ビットの浮動小数点、左右が交互)。
  動くことを確かめてある USB SPDIF Adapter と同じ形なので、いまの経路の作りのまま扱える見込みが高い。
- **サンプリング周波数は、装置によって違う**(内蔵スピーカーは 96 kHz)。経路とエンジンは、装置の周波数で作る必要がある。
  いまも、出力装置の周波数で作っている(段階3)。
- **ディスプレイのスピーカーは、macOS からは音量を変えられない。** USB SPDIF Adapter と同じである。
  つまり、ディスプレイのスピーカーでは、アプリの音量調整が有効になる(アプリの音量と音量キーで、音量を変えられるようになる)。
- **内蔵スピーカーは、macOS で音量を変えられる。** アプリの音量調整は無効になる(仕様書 4.1)。

## 2. 装置が自分で音量を変えられるかの見分け方

Core Audio の、次の値のどれかが「あって、変えられる」とき、装置が自分で音量を変えられるとする。

| 値 | 意味 | USB SPDIF Adapter | Mac miniのスピーカー | DELL S2722QC |
| --- | --- | --- | --- | --- |
| `kAudioDevicePropertyVolumeScalar`(出力、全体) | 全体の音量 | なし | あり・変えられる | なし |
| 同(チャンネル 1、2) | 左右のチャンネルごとの音量 | なし | なし | なし |
| `'vmvc'`(出力) | macOS のメニューバーの音量が使う、まとめの音量 | なし | あり・変えられる | なし |

- この Mac の3つの出力先では、全体の音量と、まとめの音量の結果が、そろっていた。
- 全体の音量を持たず、チャンネルごとの音量だけを持つ装置もあるので、チャンネル 1、2 も調べる。
- 値を読めなかったとき(見分けられないとき)は、「変えられない」として扱う。アプリの音量調整が有効になり、
  音量を変えられない装置から最大音量が出ることを防ぐ(まちがえた場合は、音量が二重に掛かるだけで、危なくない)。

## 3. 出力先の切り替えのときに起きること(利用者が操作し、アプリの記録を Claude が読んだ)

アプリに記録を足して(`SimpleEqualizer/OutputResearch.swift`)、利用者に操作してもらった(2026-10-14)。
アプリの動きは変えていない(加工の対象は USB SPDIF Adapter のまま)。
記録の場所は `~/Library/Application Support/SimpleEqualizer/research-log.txt`。

### 3.1 経路を作るのにかかる時間

「音声の加工」を切って入れ直す操作を、3回行った(起動時の1回を含めて、開始は4回)。

| 測ったもの | 値 |
| --- | --- |
| 経路を作って始めるまで(タップ、集約装置、エンジン、コールバックの登録と開始) | 72〜93 ミリ秒 |
| 加工を始めてから、最初のコールバックが呼ばれ、最初の音を受け取るまで | 99〜116 ミリ秒 |
| 片付け(音をなめらかに消す時間を含む) | 37〜54 ミリ秒 |

- 最初のコールバックまでの時間は、メインスレッドで 5 ミリ秒おきに見て測ったので、実際より少し大きい(上限の見積もり)。
- **出力先が変わるたびに経路を作り直すと、片付けと作り直しで、合わせて 150 ミリ秒ほど、加工なしの音が出る見込みである。**
  音量を変えられない装置(USB SPDIF Adapter、ディスプレイ)では、その間、最大音量で出る。

### 3.2 来る知らせ

| 操作 | 来た知らせ(順に) |
| --- | --- |
| 出力先をほかの装置に切り替える | 「いまの出力先が変わった」が1回 |
| 出力先を USB SPDIF Adapter に戻す | 「いまの出力先が変わった」。その 0.25〜0.32 秒あとに、「対象の装置が動き始めた」 |
| USB SPDIF Adapter のケーブルを抜く | 「対象の装置が使えなくなった」→「装置の一覧が変わった」→「いまの出力先が変わった」(ディスプレイになった)。全部で 12 ミリ秒のあいだ |
| ケーブルを差し直す | 「装置の一覧が変わった」→ 10 ミリ秒あとに「いまの出力先が変わった」(macOS が、自動で USB SPDIF Adapter に戻した) |
| スリープ | 「スリープに入る」。コールバックが呼ばれなくなる |
| 復帰 | 「画面が復帰した」→ 10 秒あとに「スリープから復帰した」→ そのあと、コールバックが、また呼ばれるようになる |

- 知らせは、同じものが2〜3回、続けて来ることがある(「動き始めた」「使えなくなった」)。同じ知らせが重なっても、1回として扱う必要がある。
- **アプリが自分で作る集約装置(「SimpleEqualizer」)も、装置の一覧に出る。** 加工を始める・切るたびに、「装置の一覧が変わった」が来る。
  出力先を追いかけるときは、自分の集約装置を、出力先の候補から外す。自分が起こした知らせで、作り直しを繰り返さないようにする。

### 3.3 いまの作り(経路を持ったままにする)で起きていること

- 出力先をほかの装置に切り替えているあいだ(約 11 秒)、**コールバックは、呼ばれ続けていた**(「呼ばれなくなった」の記録がない)。
  USB SPDIF Adapter 用の経路は、出力先でないあいだも動いている。だから、戻したときに、すぐ加工が続く(作り直しの時間がない)。
- **ケーブルを抜いているあいだ(約 20 秒)も、コールバックは、呼ばれ続けていた。** 抜くと、集約装置は一覧から消えるが、
  差し直すと、集約装置も一覧に戻り、そのまま加工が続いた。アプリは、何もしていない。
- スリープのあいだは、コールバックが止まる。復帰すると、また呼ばれる。アプリは、何もしていない。

### 3.4 利用者が聴いた結果

利用者が確かめた(2026-10-14、`private/memo.md`)。

- 出力先を USB SPDIF Adapter に戻したとき(2回)に、大きな音は出なかった。
- ケーブルを差し直したあと、音は、加工された音量で出た。
- スリープから復帰したとき、音に変化はなかった。

記録から読み取ったこと(経路を持ったままにしていれば、戻した瞬間に切れ目がない)と、合っている。

## 4. TICKET-003 の作りへの影響

- 出力先が変わるたびに経路を作り直す作り(TICKET-003 の案1)は、音量を変えられない装置に戻すたびに、
  150 ミリ秒ほど最大音量が出るおそれがあるので、採らないほうがよい。
- いまの作り(経路を持ったままにする)は、戻した瞬間に切れ目がないことが、記録からも分かった。
  これを、音量を変えられない装置(USB SPDIF Adapter、ディスプレイ)の全部に広げる案(TICKET-003 の案2)が、有力である。
- 経路を複数持つと、出力先でないあいだも、その数だけコールバックが動く。負荷がどのくらい増えるかは、測っていない。

利用者の判断(2026-10-14): **案A で進める。** 音量を変えられない装置(USB SPDIF Adapter、ディスプレイ)の経路は、
つながっている間、持ったままにする。音量を変えられる装置(内蔵スピーカー)の経路は、出力先になったときだけ作る。
負荷は、作ってから測り、目標(CPU 使用率 3% 以下)を超えるようなら、相談する。
