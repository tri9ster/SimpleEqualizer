# 登録なしでの配布と署名の調査(2026-10-18)

配布の TICKET-006 のための調査。Apple Developer Program に登録しない前提で、ビルド済みのアプリをどう署名して配るかを決める。

## 1. 結論

- **署名は、自分で作る証明書(自己署名)で行う。** 版を上げても許可が残る見込みで、署名に個人の情報が入らない。
- **アプリの識別子を、公開してよいものに変える。** いまの識別子には、利用者の名前が入っている。ビルド済みのアプリの中に、そのまま入る。
- 配布物は zip にする。開くときに警告が出ることと、開き方を README に書く。
- 開発用の証明書(Apple Development)で署名したアプリは、配らない。署名の中に、利用者のメールアドレスが入っている。

## 2. 分かったこと

### 2.1 いまの署名とアプリに入っている情報(Release のアプリで確かめた)

| 入っているもの | 場所 | 公開してよいか |
| --- | --- | --- |
| アプリの識別子 | アプリの `Info.plist`、署名 | **よくない。利用者の名前が入っている** |
| 証明書の名前(Apple Development: …) | 署名 | **よくない。利用者のメールアドレスが入っている** |
| チームの番号 | 署名 | 個人情報ではないが、出さずに済むなら出さない |

- アプリの識別子と証明書の名前は、配布物を受け取った人なら、誰でも `codesign -dvv` などで読める。
- 値は、この資料にも書かない(`CLAUDE.md`)。

### 2.2 ほかの人の Mac で開くとき(Gatekeeper)

- Apple の公証を受けていないアプリは、ダウンロードして開くと、macOS が止める。どの署名の方式でも同じ(公証には Developer ID が要る)。
- macOS 15 からは、右クリックの「開く」で通る方法がなくなった。開こうとして止められたあと、
  システム設定の「プライバシーとセキュリティ」の下のほうにある「このまま開く」を押す(管理者のパスワードを求められる)。
- macOS 15.1 で「このまま開く」が出なかったという報告と、出たという報告がある。**macOS 27 での様子は、実際に試して確かめる。**
- 詳しい人向けの別の方法: ターミナルで、ダウンロードした印(quarantine)を外す(`xattr -dr com.apple.quarantine <アプリ>`)。
- 出典: [Macworld](https://www.macworld.com/article/2457844/what-to-do-when-you-cant-open-an-app-you-just-installed-in-macos-sequoia.html)、
  [OSNews](https://www.osnews.com/story/141055/bug-or-intentional-macos-15-1-completely-removes-ability-to-launch-unsigned-applications/)、
  [christiantietze.de](https://christiantietze.de/posts/tags/gatekeeper/)

### 2.3 版を上げたときに、許可が残るか

macOS は、許可(システム音声の録音、アクセシビリティ)を、アプリの署名から決まる「本人を確かめる条件」(designated requirement)に結びつける。

| 署名の方式 | 本人を確かめる条件 | 版を上げたとき |
| --- | --- | --- |
| その場かぎりの署名(ad-hoc) | そのビルドの中身の指紋(cdhash)だけ。ビルドのたびに変わる | **許可が外れる。** 設定の画面ではオンのままに見えるのに効かない、という報告がある |
| 自己署名の証明書 | 識別子と、その証明書 | 同じ証明書で署名し続ければ、残るという報告がある(6回入れ替えて残った) |
| 開発用の証明書(いまの方式) | 識別子と、証明書の名前 | 残る(このプロジェクトで、ずっとそうだった)。ただし配れない(2.1) |
| Developer ID(登録が要る) | 識別子と、チームの番号 | 残る。警告も出ない |

- 自己署名の場合の条件の中身は、作ってから `codesign -d -r-` で確かめる。報告は1つのプロジェクトのものなので、このアプリでも試して確かめる。
- 証明書(とその秘密の鍵)をなくすと、次の版から、全員が許可を出し直すことになる。バックアップが要る。
- 出典: [Apple Developer Forums(ad-hoc で許可が外れる理由)](https://developer.apple.com/forums/thread/795739)、
  [shannoncoat の記録(自己署名で許可が残った)](https://git.bdeshi.space/bdeshi/shannoncoat/src/branch/main/.gitignore)、
  [Badgeify(証明書を変えると許可の出し直し)](https://docs.badgeify.app/troubleshooting/regrant-accessibility-permissions)

### 2.4 ソースからビルドする人

- `Config/Signing.xcconfig` がない状態では、識別子が空になり、署名は ad-hoc(`-`)になる(新しく取得した状態で、設定を読んで確かめた。ビルドはしていない)。
  識別子が空のままでは、ビルドできないか、できても許可がうまく働かない見込み。
- 案: 公開してよい識別子を `Config/Project.xcconfig` に初期値として書き、署名は ad-hoc を初期値にする。
  自分の証明書を使いたい人は、`Signing.xcconfig` で上書きする。

### 2.5 識別子を変えたときの影響

- 設定とプリセットの保存先は、識別子ではなく、決まったフォルダ名(`~/Library/Application Support/SimpleEqualizer/`)。識別子を変えても残る。
  `UserDefaults` など、識別子に結びつく保存は使っていない(コードを調べた)。
- 利用者の Mac では、別のアプリとみなされる。許可(システム音声の録音、アクセシビリティ)を1回出し直し、ログイン時の起動を登録し直す。
- `CLAUDE.md` の「識別子は一度決めたら変えない」は、ほかの人に配る前の、いまだけ例外にする(配ったあとに変えると、全員が出し直すことになる)。

### 2.6 配布物の形

- zip: `ditto -c -k --keepParent` で作れる(macOS の標準の道具)。開くと、そのままアプリが出てくる。
- dmg: `hdiutil` で作れる。アプリケーションのフォルダへのショートカットを置ける。少し手間が増える。
- 案: zip。どちらでも、Gatekeeper の扱いは同じ。

## 3. 決めること

1. 署名の方式(案: 自己署名の証明書)。
2. アプリの識別子を変えるか、何にするか(案: GitHub のアカウント名を使う形。例 `io.github.<アカウント名>.SimpleEqualizer`)。
3. 配布物の形(案: zip)。

## 4. 決めたことと、試した結果(2026-10-18)

利用者が決めた: 自己署名の証明書、識別子は `io.github.tri9ster.SimpleEqualizer`、配布物は dmg。

試験は、デスクトップの試験用フォルダで行った(置き場所は、配布の TICKET-008 で決める)。
dmg には、インターネットから落としたのと同じ印(quarantine)をつけた。

| 試験 | 結果 |
| --- | --- |
| 署名の中身 | 識別子、証明書の名前(個人の情報を含まない)だけ。チームの番号なし。本人を確かめる条件は「識別子」と「証明書」 |
| 配布物の中の文字 | 名前、メールアドレス、利用者の環境のパスは入っていない。macOS が付ける出どころの印(`com.apple.provenance`)は残るが、中身は番号だけ |
| はじめて開く(macOS 27) | 「"SimpleEqualizer.app" は開いていません」が出る(ボタンは「ゴミ箱に入れる」と「完了」)。システム設定の「プライバシーとセキュリティ」の「セキュリティ」の欄に「このまま開く」が出て、押すと開けた。macOS 全体の保護の設定は変えていない |
| 許可を出す | システム音声の録音は、求められて出せた。**アクセシビリティは、「許可を求める…」を押しても一覧に出ず、「+」で足す必要があった**(理由は分かっていない) |
| ビルド番号を上げた版に入れ替える(指紋は変わり、条件は同じ) | 開くときに、また止められ、「このまま開く」が要った。**許可は出し直さずに、音の加工も音量キーも効いた** |

- アクセシビリティの一覧に出なかった理由の候補: 自己署名の証明書、新しい識別子、iCloud と同期しているデスクトップの上で動かしたこと。
  `/Applications` に置いたときに同じことが起きるかを、配布の TICKET-008 で確かめて切り分ける。
- 試験 2 のあと、動いていたアプリは、試験用フォルダからではなく、macOS が一時的な場所へ移して動かす状態(App Translocation)だった。
  それでも許可は残っていた。アクセシビリティの一覧に出なかったことと関係するかは、分かっていない(理由の候補に足す)。
- 自己署名の証明書の有効期限は 2036 年 10 月。作り直すと、使う人全員の許可が外れるので、作り直さない(`CLAUDE.md`)。
- 開き方の案内は、README(配布の TICKET-007)と、dmg の中のファイル(`tools/dmg-guide.txt`)に書く。
  アプリは止められている間は動かないので、アプリ自身では案内できない。
