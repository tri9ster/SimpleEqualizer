# SimpleEqualizer 仕様書

- 版: 0.30(草案)
- 作成日: 2026-10-12
- 状態: 実現方法は案A に決定(2026-10-12)。試作で、案A が実機で成り立つことを確かめた(2026-10-12)。段階4(プリセット)まで完了(2026-10-13)。長時間の確認も済んだ。次は段階5(仕上げ)。

## 1. 背景と目的

Mac から「Cubilux USB-C → S/PDIF(光デジタル)ケーブル」を通して SONOS Ray に音を出している。
この構成では、macOS の音量調整(キーボードの音量キー、メニューバーのスライダー)が効かない。

原因は、光デジタル出力が「音量調整の機能を持たない出力装置」として macOS に認識されることにある。
macOS は装置側に音量調整の機能があるときだけ音量を変えられるので、この装置ではスライダーが無効になる。

SimpleEqualizer は、Mac の中で音声信号そのものを加工することで、次の3つを実現する。

1. 音量を変更する。
2. イコライザー(周波数帯ごとの増減)を調整する。
3. イコライザーの設定を名前をつけて保存し、あとから呼び出す。

## 2. 対象環境

2026-10-12 に実機で確認した内容。

| 項目 | 内容 |
| --- | --- |
| Mac | Mac mini(Apple シリコン、arm64) |
| OS | macOS 27.0.1 |
| 出力装置 | 「USB SPDIF Adapter」(USB 接続、2ch、48 kHz / 24 ビット) |

## 3. 実現方法の提案

### 3.1 案の一覧

| | 案A: システム音声の横取り(Core Audio タップ) | 案B: 仮想オーディオ装置 | 案C: SONOS をネットワーク経由で操作 |
| --- | --- | --- | --- |
| しくみ | macOS の標準 API でシステム全体の音を取り出し、元の音は消す。加工した音を光デジタル出力へ流す | 音量調整つきの仮想の出力装置を macOS に追加し、既定の出力にする。アプリがそこから音を受け取り、加工して光デジタル出力へ流す | 音声には触らない。同じ LAN にいる SONOS Ray へ命令を送り、SONOS 側の音量と音質設定を変える |

| 音量キー | アプリがキー入力を横取りする必要がある(アクセシビリティの許可が要る) | 何もしなくても効く | アプリがキー入力を横取りする必要がある |

| 音の遅れ | 数十ミリ秒ほど発生する見込み(要実測) | 数十ミリ秒ほど発生する見込み(要実測) | なし |

| 開発の規模 | 中 | 大(ドライバーを自作する場合)/中(既存品に頼る場合) | 小 |

参考として、開発しない選択肢もある。eqMac や SoundSource などの既存アプリは、案A・案Bと同じしくみで同じ目的を満たす。

### 3.2 決定

**案A で進める(2026-10-12 決定)。案C はあとから追加できる構造にしておく。**

- 案A は、音量・イコライザー・保存と呼び出しの3つを、追加インストールなしで満たせる。
- 案B は音量キーがそのまま効く利点があるが、ドライバーの自作と保守の負担がその利点を上回る。
- 案C は単独では 10 バンドのイコライザーを満たせない(SONOS 側で変えられるのは低音・高音だけ)。
  ただし音量を SONOS 側で変えれば音質が落ちないので、案A と組み合わせる価値がある。第2段階の候補とする。

### 3.3 試作で確かめた点と、未検証の点

2026-10-12 の試作で、実機で確かめた(記録は `research/Prototype_Result.md`)。

- 案A の API(`AudioHardwareCreateProcessTap`)は、macOS 27 と USB SPDIF Adapter の組み合わせで動く。
  元の音は消え、加工した音だけが出る。
- 音の遅れは、動画の視聴で気にならない。装置が申告している遅れとバッファの合計は 15.8 ミリ秒。
- アプリを止めたとき、終了したとき、異常終了したときは、音が元の経路に戻る。
- スリープ、出力先の切り替え、ケーブルの抜き差しのあとも、設定を保ったまま動く。
- 取り出した音を `AVAudioEngine` に通して加工できる(7章の構成が成り立つ)。

試作の前に、実機で確かめた(記録は `research/Prototype_PreCheck.md`)。

- USB SPDIF Adapter には音量調整の機能がない(1章の原因の裏づけ)。
- USB SPDIF Adapter は 24 ビット出力に対応していて、いまも 48 kHz / 24 ビットで動いている。
  16 ビットの場合に比べ、音量を下げたときの音質低下は小さい。

まだ確かめていない。

- SONOS Ray がネットワーク経由の音量・音質の命令を、光デジタル入力の再生中にも受け付けるか(案C。第2段階の候補)。

分かっている課題。

- 再生する音源のサンプリング周波数が変わる(44.1 kHz と 48 kHz)と、音がとぎれた。段階5 で直した(2026-10-15)。
  周波数が変わったら、新しい周波数で、加工の経路を作り直す。

## 4. 機能仕様(案A 前提)

### 4.1 音量

- 0〜100 の範囲で変更できる。初期値は 100(元の音量のまま)。
  2026-10-12 に 30 から変えた。100 でも、アプリを使う前より音が大きくなることはない。
  30 は、音が小さすぎて聞こえなかった(利用者の判断)。
- 保存してあった音量が使えないとき(値が読めない、足りない、範囲の外、設定のファイル全体が読めない)は、
  100 ではなく 30 で始める。前に音量を小さくして使っていたかもしれないので、壊れた設定で大きな音を出さないため。
- 変更の方法は3つ: メニューバーのスライダー、キーボードの音量キー、消音の切り替え。
- 音量キーは1回で 1/16 ずつ変わる(macOS 標準と同じ刻み)。Option + Shift を押しながらだと 1/64 ずつ変わる。
  - スライダーで決めた、刻みの途中の音量からは、となりの刻みへ動く。
  - 消音しているときに、上げる・下げるを押すと、消音を解く。消音のキーは、押し続けても1回だけ切り替わる。
  - アプリが音量キーを受け取るのは、加工していて、音量調整が有効なときだけ。それ以外は、macOS に任せる。
- 音量キーを押したときは、macOS 標準に似た音量表示を画面に出す。
- 音量の数値と実際の音の大きさは、聴感に合うように対応づける。100 で元の音量、0 で無音。
  対応は、音量を 0〜1 に直した値の3乗を倍率にする(50 で約 −18 dB、30 で約 −31 dB、10 で −60 dB)。
- 音量と消音の状態は保存し、次回の起動時に復元する。
- アプリによる音量調整には、有効と無効がある(2026-10-12 追加)。
  - 有効のとき: 上のとおり、アプリが音量を変える。
  - 無効のとき: アプリは音量を変えない(元の音量のまま)。音量は macOS の音量調整で変える。
    スライダー、消音、音量キーは、アプリでは働かない。
  - 目的: 「Mac miniのスピーカー」のように macOS の音量調整が効く出力先で、音量が二重に掛かるのを防ぐ。
  - 有効・無効は、出力先の装置の種類で自動で決まる。利用者が切り替える設定は持たない。
    自分で音量を変えられない装置(USB SPDIF Adapter など)では有効、変えられる装置(内蔵スピーカーなど)では無効。
    切り替え忘れで、音量を変えられない装置から最大音量が出ることを防ぐ。
- 音量と消音の状態は、出力先ごとに覚える(音量調整が有効な出力先だけ)。初めて使う出力先は、音量 100、消音なしで始まる。

### 4.2 イコライザー

- 10 バンド: 31 / 62 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz。
- 各バンドは −10〜+10 dB を 0.5 dB 刻みで調整できる。
- イコライザーの有効・無効を1操作で切り替えられる(効果の聴き比べ用)。
- 増幅によって音が割れないよう、出力の直前にリミッター(上限を超えた分を抑える処理)を入れる。
  音量を下げている間は増幅しても上限を超えないので、リミッターが働くのは音量が最大付近のときだけになる。
  アプリによる音量調整が無効のとき(4.1)は、いつも元の音量なので、増幅するとリミッターがいつも働き、音がつぶれる。
  そこで、このときは、増幅した分だけ、全体を自動で下げる(1つのバンドを +6 dB 上げているなら、全体を 6 dB 下げる)。
  となり合うバンドを上げていると、山が重なって、増幅が1つのバンドの量より大きくなる(全部を +10 dB にすると、約 +15.5 dB)。
  下げる量は、この重なりを含めて見積もる。
  下げるだけの設定なら、何も下げない。小さくなった分は、macOS の音量で上げる。
  自動で下げるのは、切にできる(初期値は入)。スピーカーごとに音量を合わせて、音質を聴き比べるときのため。
  切のときは、リミッターが働くことがある(2026-10-14、利用者の判断)。
- スライダーを動かしている間も、音切れなく即座に反映する。
- イコライザーのウィンドウでは、矢印キーで操作できる。
  - 左右: 調整するバンドを選ぶ。
  - 上下: 選んでいるバンドを 0.5 dB ずつ増減する。Shift を押しながらだと 2 dB ずつ増減する。
  - 選んでいるバンドは、枠や色で分かるように表示する。
- SONOS Ray は小型でサブウーファーがないため、31 Hz のバンドはほとんど効かない見込み。
  標準的な 10 バンドの並びを保つために残す。

### 4.3 ラウドネス

小さい音量では低音と高音が聞こえにくくなる。これを補う機能で、イコライザーとは別に働く。

- 効き具合を、強さ(0〜100)のスライダーで決める。0 で切。初期値は 0。
  2026-10-12 に、入・切のスイッチから変えた(利用者の要望。聴いて、効き具合を自分で変えたい)。
- 強さが 0 でないとき、音量に応じて低音と高音を自動で持ち上げる。
- 補正量は、アプリの音量値と、強さで決める。
  - 音量 100 で補正なし。音量を下げるほど補正が増え、音量 50 あたり(18 dB 下げたところ)で上限に達する。
    それより音量を下げても、補正は増えない(小さい音量で効きすぎないようにする)。
  - 強さ 100 での上限は、低音(100 Hz より下)+15 dB、高音(8 kHz より上)+6 dB。補正量は、強さに比例する。
    はじめは +10 dB、+4 dB としたが、利用者が聴いて、上限を上げた(2026-10-12)。
  - 消音の切り替えでは、補正量は変わらない。
- 補正は、いちばん強くしても、いつも音量による減衰より小さい。ラウドネスだけで、音が元の音量を超えることはない。
- イコライザーを無効にしても、ラウドネスは効いたままにする。
- 強さはプリセットに含めず、音量や消音と同じ「前回の状態」として保存する。
- アプリによる音量調整が無効のときは、ラウドネスを使えない(補正量を決める音量値がないため)。
- 補正量は SONOS Ray で聴いて決めた値である。ほかの出力先では合わない場合がある。強さのスライダーで合わせる。
- SONOS Ray 本体にもラウドネスの設定がある。二重にかかるので、アプリ側を使うときは SONOS 側を切る。

### 4.4 プリセット(保存と呼び出し)

- 現在のイコライザー設定(10 バンドの値)に名前をつけて保存できる。
- 保存したプリセットを一覧から選んで呼び出せる。メニューバーからも直接選べる。
- プリセットの上書き、名前の変更、削除ができる。
- 初めから「フラット」(すべて 0 dB)を用意する。これは削除できない。
- 最後に使っていたプリセットを、次回の起動時に復元する。
- プリセットを1つのファイルとして書き出し、読み込める(バックアップ用)。
  - 書き出しは、全部のプリセット(「フラット」を除く)を1つのファイルに書く。
  - 読み込みは、いまの一覧に足す(置き換えない)。同じ名前があるときは、読み込む側の名前に番号をつける(「映画 2」)。
    読み込んだだけでは、音は変わらない。
  - 読み込めるのは、1つのファイルにつき 500 件まで、大きさは 2 MB まで。
  - 保存していない変更があるまま書き出すときは、確かめる画面を出す(書き出されるのは、保存してある値)。
- 同じ名前のプリセットは作れない。名前は 30 文字まで。空の名前は使えない。
  名前は、前後の空白を取り、続いた空白や改行を空白1つにまとめ、見えない文字を取り除いてから、調べて保存する。
- 「フラット」は、上書きと名前の変更もできない。
- プリセットを削除したあとは、「フラット」に切り替わる(値はすべて 0 dB になり、保存していない変更の印はつかない)。
  音を下げる設定のプリセットを消したときは、音が大きくなるので、確かめる画面で伝える。
  値を残して「フラット *」にする案は、利用者には状況が分かりにくいので、採らなかった(2026-10-13、利用者の判断)。
- すべて 0 dB の値でプリセットを上書きするときは、確かめる画面を出す。
- 保存していない変更があるときに別のプリセットを選んだら、確かめる画面を出す。
- プリセットに含めるのは、10 バンドの値だけである。音量、消音、ラウドネスの強さ、イコライザーの有効・無効は含めない。

### 4.5 出力先との連動

2026-10-12 に、「選んだ出力装置だけを加工する」から「いまの出力先を加工する」へ変えた。

- 加工の対象は、macOS のいまの出力先とする。どの出力先にも、同じ加工(イコライザー、ラウドネス)を掛ける。
- 出力先が変わったら、加工の対象も一緒に切り替える。同時に加工するのは1つだけである。
- イコライザーの設定とプリセットは、出力先ごとには覚えない。
  出力先に合わせた設定は、利用者がプリセット(「SONOS 用」「内蔵スピーカー用」など)を切り替えて使う。
- 出力先ごとに「加工しない」を選ぶ機能は持たない。
- 音量調整だけは、出力先によって有効・無効が変わる(4.1)。
- 出力先が抜かれたときは、macOS が切り替えた先の出力先を加工する。スリープから復帰したときは、そのまま加工を続ける。
- アプリが扱えない形式の出力先(動くことを確かめていないもの)では、音声に触らず、その旨を表示する。
- 出力先を切り替えた瞬間に、切り替え先の音が加工なしの最大音量で出ないようにする。
  そのために、音量を変えられない出力先(アプリの音量調整が有効な出力先)には、いまの出力先でないあいだも、加工の経路を持ったままにする
  (2026-10-14 決定。経路を作り直すと 0.15 秒ほどかかり、その間、加工なしの音が出るため)。
  「同時に加工するのは1つだけ」は、利用者から見た動きのことで、内部では、経路を複数持つ。
- 音量を変えられる出力先の経路は、いまの出力先になったときに作る。作る間は加工なしの音が出るが、macOS の音量が効いている。
- 装置が抜かれたら、その経路を片付ける。差し直されたら、新しく作る(作る間の 0.15 秒ほどは、加工なしの音が出る)。

確かめる対象は、USB SPDIF Adapter、内蔵スピーカー(「Mac miniのスピーカー」)、ディスプレイのスピーカーの3つである
(2026-10-14、利用者がふだん使う出力先)。どれも、出力が 1 本、2 チャンネルである。この形でない出力先は、扱わない。
AirPlay は、利用者が試して、イコライザーが効いた(くわしくは確かめていない)。Bluetooth は、確かめていない。
形が合う出力先(出力 1 本、2 チャンネル)は、確かめる対象でなくても、加工する。

### 4.6 常駐と起動

- メニューバーに常駐する。Dock にはアイコンを出さない。
- ログイン時に自動で起動する設定を持つ(初期値は無効)。
- アプリを終了したら、音声は加工なしの元の状態に戻る(音量は最大のまま出る点を、終了時に注意表示する)。

### 5.1 メニューバーのポップアップ

メニューバーのアイコンをクリックすると開く。日常の操作はここで完結する。

- イコライザーの有効・無効の切り替え

- プリセットの選択
- 「イコライザーを開く」「設定」「終了」

確かめる画面(プリセットの削除などを含む)の「進める」ボタンは、Return キーでは押せない(2026-10-13)。Esc でキャンセルできる。

### 5.2 イコライザーのウィンドウ

- 10 本の縦スライダー(矢印キーでも操作できる。選んでいるバンドを強調して表示する)
- 各スライダーの下に、現在の値(dB)

## 6. 保存するデータ

保存先は `~/Library/Application Support/SimpleEqualizer/`。形式は JSON。

`presets.json`(プリセットの一覧):

```json
{
  "version": 1,
  "presets": [
    {
      "id": "UUID",
      "name": "映画",
      "gainsDb": [0, 4.0, 3.0, 1.5, 0, 0, 1.0, 2.0, 2.5, 2.0]
    }
  ]
}
```

`gainsDb` は 31 Hz から 16 kHz の順に 10 個の値を並べる。

`state.json`(前回の状態):

```json
{
  "version": 1,
  "outputs": {
    "装置の UID": { "volume": 30, "muted": false }
  },
  "equalizerEnabled": true,
  "equalizerGainsDb": [0, 4.0, 3.0, 1.5, 0, 0, 1.0, 2.0, 2.5, 2.0],
  "loudnessAmount": 40,
  "selectedPresetId": "UUID",
  "autoLowerEnabled": true,
  "volumeKeysEnabled": true
}
```

- `outputs`: 出力先ごとの音量と消音。装置は UID(macOS が装置につける識別子)で見分ける。
- 音量が読めない、足りない、範囲の外のときは、30 として読む(初期値の 100 にはしない。4.1)。
- `equalizerEnabled`、`equalizerGainsDb`、`loudnessAmount`: イコライザーの有効・無効、いまの 10 バンドの値、
  ラウドネスの強さ(0〜100)。出力先に共通(2026-10-12 追加。版の番号は 1 のまま)。
  - 項目がないとき(前の版のアプリが作ったファイル)は、イコライザーは有効ですべて 0 dB、ラウドネスの強さは 0。
  - ラウドネスの強さが、読めない、範囲の外のときは、0 にする(近い端の 100 に丸めない)。
  - 開発の途中で、強さではなく有効・無効(`loudnessEnabled`)で保存していた時期がある。
    `loudnessAmount` がなく、`loudnessEnabled` が有効のファイルは、強さ 50 として読む。保存するときは、強さだけを書く。
  - `equalizerGainsDb` の個数が 10 でないとき、範囲の外の値や読めない値が1つでもあるときは、すべて 0 dB にする
    (近い端の +10 dB に丸めない)。
  - 有効・無効が、書いてあるのに読めないときは、無効にする。
- `volumeKeysEnabled`: 音量キーで、アプリの音量を変えるか(2026-10-15 追加)。項目がない、読めないときは、入。
- ログイン時に起動するかどうかは、macOS が覚えるので、書かない。
- `autoLowerEnabled`: 音量調整が無効の出力先で、増幅した分だけ全体を自動で下げるか(2026-10-14 追加)。項目がない、読めないときは、入。
- `selectedPresetId`: 選んでいるプリセットの `id`(2026-10-13 追加)。項目がない、読めない、一覧にない `id` のときは、「フラット」を選んでいるものとする。
  `equalizerGainsDb` は、保存していない変更を含む、いまの値として使う(選んでいるプリセットの値と違えば、変更の印がつく)。

`presets.json` には、「フラット」を書かない(アプリが、いつも一覧の先頭に足す)。
書き出しと読み込み(バックアップ)のファイルも、`presets.json` と同じ形である。

読めないファイルの扱い(`state.json` と `presets.json` に共通):

| 場合 | 動き |
| --- | --- |
| 全体が壊れていて読めない | 別名(`state.broken-<日時>.json`、`presets.broken-<日時>.json`)で残し、初期状態で起動する |
| 新しい版のアプリが作ったファイル。版の番号が整数として読めないファイル。あるのに読めないファイル | 触らない。初期状態で起動し、上書きしない |
| `presets.json` に、プリセットの一覧がない | 全体が壊れているものとして扱う |
| `presets.json` の一部のプリセットだけが壊れている | そのプリセットは読まない。元のファイルの写しを別名(`presets.partial-<日時>.json`)で残し、読めた分で書き直す |

値が範囲の外のプリセットは、近い端(+10 dB)に丸めず、読まない。

## 7. 技術構成

| 項目 | 採用するもの |
| --- | --- |
| 言語・画面 | Swift、SwiftUI(メニューバー常駐は `MenuBarExtra`) |
| 音声の取り出し | Core Audio のプロセスタップ(`AudioHardwareCreateProcessTap`、元の音を消す設定)と集約装置 |
| 音声の加工 | `AVAudioEngine`。イコライザーは `AVAudioUnitEQ`(10 バンド)、ラウドネスは別の `AVAudioUnitEQ`(低域・高域のシェルフ型フィルター2つ)。続けて音量、リミッターの順 |
| 加工の呼び出し方 | 集約装置の入出力コールバックの中から、エンジンを「手動レンダリング(リアルタイム)」で呼ぶ。エンジンに装置を持たせる方式より遅れが増えない |
| 音声のコールバック | C で書く。画面、設定、エンジンの組み立ては Swift。エンジンとコールバックをつなぐところだけ Objective-C。理由は 12章 |
| 音量キー | `CGEventTap` でキー入力を受け取り、標準の動作を止める |
| 自動起動 | `SMAppService` |
| 配布 | 自分の Mac だけで使う。アプリの形(`.app`)にまとめ、開発用の証明書で署名する。サンドボックスは使わない |

処理の流れ:

```
各アプリの音 → タップ(元の音は消す) → イコライザー → ラウドネス → 音量 → リミッター → USB SPDIF Adapter → SONOS Ray
```

注意点:

- 自分自身の出力をタップの対象から外す。外さないと音が循環する。
- 取り出せるのは通常の音声(PCM)だけである。Dolby Digital などの圧縮された信号をそのまま通す再生は加工できない。
- 「システム音声の録音」の許可には、アプリの `Info.plist` に `NSAudioCaptureUsageDescription` が必要になる。

## 8. 必要な許可

| 許可 | 用途 | 拒否された場合 |
| --- | --- | --- |
| システム音声の録音 | 音声の取り出し | アプリは音量を変えられない。案内の画面を出し、設定を開けるようにする |
| アクセシビリティ | 音量キーの受け取り | 音量キーだけ使えない。メニューバーからの操作は使える |

### 8.1 「システム音声の録音」の許可がないときの案内(2026-10-12 追加)

- 許可がなくても、アプリは「動いている」状態になり、取り出した音は無音になる(実機で確認)。macOS には、この許可の状態をアプリから調べる方法がない。
- そこで、状況から判断する。次の状態が 10 秒ほど続いたら、音を取り出せていないと判断する。
  - ほかのアプリが、対象の出力先へ音を出している。
  - アプリは、加工を始めてから、無音でない音を一度も受け取っていない。
- 判断したら、次のことをする。
  - 案内の画面を出す(起動してから1回だけ)。「設定を開く」で、システム設定の「システム音声の録音」の画面を開く。
  - メニューバーのアイコンを、警告の印に変える。
  - ポップアップに、説明と「設定を開く」を出す。音を受け取れるようになったら消す。
- 限界: ほかのアプリが、無音のまま出力を動かしている場合(一時停止中の動画など)は、許可があっても、まちがって案内が出ることがある。
- 許可を出したあとは、アプリを起動し直す。

## 9. 性能などの目標

- CPU 使用率は、経路を2本持った状態(段階5)で、静かに再生している間、2.5〜3.0% だった(2026-10-14)。画面を操作している間は、8% ほどまで上がる。
- 音の遅れ: 50 ミリ秒以下を目標とする。試作では、装置の申告とバッファの合計が 15.8 ミリ秒だった
  (再生するアプリ側と SONOS 側の遅れは含まない)。目標は変えない。
- CPU 使用率: 再生中で 3% 以下。試作では、音声の処理が約 1.2% だった。
- 音切れ・雑音を出さない(スライダー操作中、装置の抜き差し時、スリープからの復帰時を含む)。
- 連続稼働しても、メモリ使用量が増え続けない。

## 11. 開発の進め方

1. 試作: タップで取り出した音を、音量を変えて光デジタル出力へ流すだけのものを作り、3.3 の未検証の点を確かめる。**完了(2026-10-12)。**
2. 音量: メニューバー常駐、音量スライダー、消音、状態の保存。**完了(2026-10-12)。**
3. イコライザー: 10 バンド、ラウドネス、リミッター。**完了(2026-10-13)。**
4. プリセット: 保存、呼び出し、編集、書き出しと読み込み。**完了(2026-10-13)。**
5. 仕上げ: 音量キー、出力先との連動(いまの出力先を加工する。4.5)、自動起動。

試作で案A が成り立つと分かったので、案B への切り替えは行わない。
試作のうち、Xcode のプロジェクト、アプリの識別子、署名の設定は引き継ぐ。音声を扱うコードは段階2 で作り直す。
