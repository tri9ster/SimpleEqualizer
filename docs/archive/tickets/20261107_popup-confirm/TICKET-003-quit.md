# TICKET-003: ✕ のボタンで終了するとき

## 概要

ポップアップの ✕ のボタンで終了するときの確かめる画面を、ポップアップの中に出す。
⌘Q、ほかのアプリからの終了の頼みは、ポップアップが閉じていることがあるので、いまのダイアログのまま残す(2026-11-07、利用者が決めた)。

2026-11-07 時点。

- ✕ のボタンは `NSApp.terminate(nil)` を呼び、終了の入口(`AppDelegate.applicationShouldTerminate`)で確かめる。
  ⌘Q と同じ道を通すため(⌘Q で確かめずに終わった実害。2026-10-20、`docs/failures.md`)。

## 対応方針・作業手順

1. ✕ のボタンは、加工中なら、ポップアップの中に確かめる画面を出す。加工していないときは、いまと同じく、確かめずに終える。
2. 進めたら終了する。終了の入口で、もう一度ダイアログが出ないようにする(ポップアップで確かめたことを、入口に伝える)。
   伝えた印は、その1回の終了だけに使う(終了が取り消されたあとに、⌘Q で確かめずに終わらないようにする)。
3. ⌘Q、ほかのアプリからの終了の頼みは、いまのまま、終了の入口でダイアログを出す。
   ポップアップの中の確かめる画面を出している間に ⌘Q を押したときの扱いを決める(案: ダイアログを出す。ポップアップの確かめる画面は閉じる)。
4. 文言、仕様書(4.7、5.1)、README の両方、`architecture.md`、`dev-log.md` を直す。
5. 利用者に確かめてもらう。**スピーカー側の音量を下げてから試す**(終了すると、最大音量に戻るため)。

## 実施結果

2026-11-07 に作り、利用者が確かめた(動作確認項目のすべてと、カードを出したままの ⌘Q で、カードが閉じてからダイアログが出ること)。

- ✕ のボタンは、加工中なら、いちばん下に確かめるカードを出す(`Confirmation.quit`)。加工していないときは、確かめずに `NSApp.terminate`。
- 「終了」を押したら、`AppDelegate.terminateConfirmedInPopup` で、終了の入口に1回だけ使える印を渡してから終える。入口は、印を消して、確かめずに終える。
- ⌘Q などで入口がダイアログを出すときは、先に知らせ(`AppDelegate.willConfirmQuit`)を送り、ポップアップはカードを閉じる。
- 加工が自動で止まったら、終了のカードも閉じる(確かめる理由がなくなるため)。
- 文言は、ダイアログと同じもの。新しい文言はない。README(英語と日本語)の ✕ のボタンの説明を直した。
- `/code-review` の指摘で、利用者が確かめたあとに直したこと:
  - 印は、`terminateConfirmedInPopup` の中だけで立て、終了の頼みから戻ってきたら必ず消す(`defer`)。
    入口が呼ばれずに戻ったときに、印が残り、あとの ⌘Q で確かめずに終わるのを防ぐ。
  - 終了の見出しとボタンの文言を、ダイアログとカードで1か所にした(`Dialogs.quitMessage`、`quitButton`)。
  - 加工が止まったら閉じるカードかを、場面の性質にした(`Confirmation.needsRunning`)。
- 指摘のうち、直さなかったこと:
  - 加工が自動で止まると、終了のカードも閉じ、終了の頼みは消える(もう一度 ✕ を押す)。仕様書 5.1 の決めたとおり。
  - ⌘Q で、加工を切るカードも閉じる。ダイアログを取り消しても、カードは戻らない。仕様書 5.1 の決めたとおり。
  - 加工を始めている途中(`.starting`)は、✕ でも ⌘Q でも、確かめずに終わる。前からの動き。`TODO.md` に書いた。
- 未確認: 直したあとの動き(印の扱いは、終了が取り消されない限り、利用者が確かめた動きと同じ)。
