# TICKET-001: テストの土台と、音量の換算

## 概要

自動テストを動かせるようにし、音量の数値(0〜100)から倍率への換算を、テストを先に書いて作る。
音を出さずに結果を確かめられる処理で、`CLAUDE.md` の「テストを先に書く」の対象。

## 対応方針・作業手順

1. Xcode のプロジェクトに、テストのターゲット(`SimpleEqualizerTests`)を足す。
   - Apple 標準のテストの仕組み(Swift Testing)を使う。外部ライブラリは足さない。
   - プロジェクトのファイルは、試作と同じく手で書く。
   - テストは、アプリを起動せずに動く形にする(起動すると音声に触るおそれがあるため)。
     そのために、音声に触らないコードを、アプリ本体とは別のまとまり(フレームワークか、テストに直接入れる形)に分ける。
     どの形にするかは、着手時に試して決め、`docs/architecture.md` に理由を書く。
2. `CLAUDE.md` の「確認方法」に、テストのコマンドを書く。
3. 失敗するテストを先に書く。確かめる内容:
   - 音量 100 で倍率 1.0(元の音量)。
   - 音量 0 で倍率 0(無音)。
   - 音量が大きいほど、倍率が大きい(逆転しない)。
   - 倍率は 0 以上 1.0 以下。範囲の外の音量(負の数、100 を超える数、数でない値)でも、この範囲に収まる。
   - 決めた対応(README の「決めてもらうこと」3)どおりの値になる(例: 音量 50 でのデシベル)。
   - デシベルから倍率、倍率からデシベルの換算が、行って戻ると元の値になる。
4. テストが失敗することを確かめてから、換算を実装する(`VolumeCurve`)。
5. テストが通ることを確かめる。

## 実施結果

2026-10-12 に実施。

行ったこと:

- 音声に触らない処理をまとめる Swift パッケージ `Core/`(`SimpleEqualizerCore`)を作った。
  アプリは、このパッケージをプロジェクトから参照して使う。
- **手順からの変更**: Xcode のプロジェクトにテストのターゲットを足す形ではなく、パッケージに分ける形にした。
  - テストは `swift test --package-path Core` で動く。アプリを起動しないので、音声に触るおそれがない。
  - プロジェクトのファイルに手で足す量が少ない(参照を1つ足すだけ)。
  - Swift パッケージは Xcode の標準の仕組みで、外部ライブラリではない。
- 換算 `VolumeCurve` を作った。対応は、利用者が決めた案ウ(3乗)。
- 試作のコードの中にあった仮の式を消し、`VolumeCurve` を使うようにした。
  これで、いまの試作のアプリも、次に起動したときから新しい対応になる(音量 30 で、これまでより 3.6 dB 大きい)。

テストの記録:

- 実装の前: 10 件のテストで 115 件の不一致(すべての倍率が 0 を返す仮の実装で確認)。
- 実装のあと: 10 件のテストがすべて通った。

決めたこと:

- 範囲の外の音量は、近い端に丸める(負の数は 0、100 を超える数は 100)。
- 数でない値(NaN)は、無音にする。安全な側に倒すため。
