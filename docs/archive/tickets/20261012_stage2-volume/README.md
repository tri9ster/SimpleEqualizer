# 段階2(音量) チケット一覧(2026-10-12)

仕様書 11章の段階2にあたる。試作を、ふだん使える形(メニューバー常駐、音量、消音、状態の保存)に作り替える。
あわせて、試作で決まった「音声のコールバックを C で書く」を行い、利用者が用意したアイコンを組み込む。

## この段階でできるようになること

- アプリがメニューバーに常駐する。Dock にはアイコンを出さない。
- メニューバーのポップアップで、音量(0〜100)を変え、消音を切り替えられる。
- 音量と消音の状態が保存され、次の起動で元に戻る。
- 起動すると、自動で加工が始まる(「開始」を押さなくてよい)。

## 範囲に入れないもの

- イコライザー、ラウドネス、リミッター(段階3)。プリセット(段階4)。
- 音量キー、音量キーを押したときの表示、出力装置の選択と連動、ログイン時の起動、設定のウィンドウ(段階5)。
- サンプリング周波数の切り替えで音がとぎれる課題(段階5)。

ポップアップのうち、イコライザー、ラウドネス、プリセット、「イコライザーを開く」「設定」は、この段階では出さない
(動かない項目を並べないため)。仕様書 5.1 の図は完成時のもの。

## 作業順序

```
TICKET-001 テストの土台と、音量の換算
    └─ TICKET-002 状態の保存と読み込み
           └─ TICKET-003 音声の経路の作り直し(コールバックを C へ)
                  └─ TICKET-004 メニューバー常駐と、音量・消音の画面
                         └─ TICKET-005 アイコンの組み込み
                                └─ TICKET-006 実機での確認とまとめ
```

- 001 と 002 を先にする理由: 音を出さずに確かめられる部分で、テストを先に書いて作る(`CLAUDE.md`)。
  音声の経路(003)と画面(004)は、ここで作った換算と保存を使う。
- 003 を 004 の前にする理由: 作り直した経路を、試作の画面のまま確かめる。
  経路と画面を同時に替えると、不具合が出たときにどちらが原因かを切り分けにくい。
- 005 を 004 のあとにする理由: メニューバーのアイコンは、常駐の画面ができてから差し替える。

### 1 の補足: 自動で加工を始めたあとの動き

- 起動すると、保存した音量(初回は 30)で加工が始まる。対象は、USB SPDIF Adapter に出ている音だけ。
- 出力先を「Mac miniのスピーカー」に切り替えると、アプリはその音に触らない。音量は macOS の音量調整で変える。
- 出力先を USB SPDIF Adapter に戻すと、同じ音量、同じ消音の状態で加工が続く。設定は残る。
  - 試作で、利用者が1回確かめた(TICKET-003 の 11。戻すと、加工された音が、変えた音量のまま出た)。
  - 段階2 では、設定を `state.json` にも保存するので、アプリを起動し直しても残る。
  - 段階2 の TICKET-006 で、もう一度確かめる。
- 確かめていないこと: 切り替えを何度も繰り返したときや、長く別の装置を使ったあとに、加工が止まる場合があるか。
  止まった場合、段階2 では、ポップアップの「音声の加工」を入れ直せば再開できる。自動で再開する処理は段階5 で作る。

### 3 の候補: 音量の数値と音の大きさの対応

| 音量 | いま(−50 dB の直線) | 案ア: −40 dB の直線 | 案イ: 2乗 | 案ウ: 3乗 |
| --- | --- | --- | --- | --- |
| 1 | −49.5 dB | −39.6 dB | −80.0 dB | −120.0 dB |
| 10 | −45.0 dB | −36.0 dB | −40.0 dB | −60.0 dB |
| 20 | −40.0 dB | −32.0 dB | −28.0 dB | −41.9 dB |
| 30(初期値) | −35.0 dB | −28.0 dB | −20.9 dB | −31.4 dB |
| 50 | −25.0 dB | −20.0 dB | −12.0 dB | −18.1 dB |
| 70 | −15.0 dB | −12.0 dB | −6.2 dB | −9.3 dB |
| 100 | 0 dB | 0 dB | 0 dB | 0 dB |

- 「2乗」「3乗」は、音量を 0〜1 に直した値を2回、3回掛けたものを倍率にする対応。0 で自然に無音になる。
- 提案: **案ウ(3乗)**。小さい側(0〜20)が早く無音に近づくので、スライダーの小さい側を使う幅が減り、
  ふだん使う大きさに幅を多く割ける。初期値の 30 での音の大きさは、いまとほぼ同じ(3.6 dB 大きいだけ)。
- **安全上の注意**: どの案でも、同じ数値での音がいまより大きくなる。初期値の 30 では、
  案アで 7 dB、案イで 14 dB、案ウで 3.6 dB 大きくなる。`CLAUDE.md` の決まりにより、選ぶ前に確認を受ける。
- 決めたあと、聴いてみて合わなければ、テストを先に直してから対応を変える(TICKET-006 の 3)。

## 音を出すときの安全(この段階での変更点)

この段階では、「起動時に音量が決まる」動きが変わる。`CLAUDE.md` の決まりに従い、次を守る。

- 音量の初期値は、はじめ 30 としていたが、TICKET-007 で 100 に変えた(利用者の判断。100 でも元の音量を超えない)。
  保存した値が読めないとき、範囲の外のときは 30 にする。
- 加工が始まる瞬間は、倍率を 0 から目標の値へなめらかに上げる。
- 加工は元の音量を超えない(倍率の上限は 1.0)。リミッターは段階3 で入れる。
- 音を試す直前には、毎回、SONOS Ray 側の音量を下げてもらう。
