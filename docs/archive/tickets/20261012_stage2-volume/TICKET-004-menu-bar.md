# TICKET-004: メニューバー常駐と、音量・消音の画面

## 概要

試作のウィンドウをやめ、メニューバーに常駐する形にする(仕様書 4.1、4.6、5.1)。
ポップアップで音量と消音を操作でき、状態が保存され、起動すると自動で加工が始まる。

## 対応方針・作業手順

### 画面(この段階のポップアップ)

```
+----------------------------------------+
| 音量                                42 |
| [消音]  =============O---------------- |
+----------------------------------------+
| 音声の加工                       [ON ] |
+----------------------------------------+
| 終了                                   |
+----------------------------------------+
```

- 「音声の加工」の切り替えは、README の「決めてもらうこと」2 による。置かない場合は外す。
- 加工できないとき(装置が見つからない、許可がない、エラー)は、ポップアップの上に理由を出す。
- 画面の文言は日本語だけ。

### 手順

1. メニューバー常駐にする(`MenuBarExtra`、ポップアップの形)。Dock にアイコンを出さない(`LSUIElement`)。
2. アプリの状態をまとめる部品(音量、消音、加工の状態)を作る。試作の `PrototypeModel` を置き換える。
   - 音量や消音を変えたら、音声の経路に伝え、状態を保存する。
   - スライダーを動かしている間は、保存をまとめる(動かすたびにファイルへ書かない)。
   - 読み込みの結果が「保存してはいけない」(`isSafeToSave` が false)のときは、保存しない。
     ポップアップに、設定を保存できないことと理由を出す。
   - 音量と消音は、出力先(装置の UID)ごとに `AppState` へ入れる。段階2 の対象は USB SPDIF Adapter だけ。
3. 起動時の動き(README の「決めてもらうこと」1 による)。
   - 保存した状態を読み込む。
   - 加工を自動で始める。音量は読み込んだ値。始められないときは、音声に触らず、理由を出す。
4. 消音: 切り替えると、音がなめらかに消える・戻る。音量の数値は変えない。
5. 終了: 「終了」を選んだら、音が最大音量に戻る注意を出し、確かめてから終える(仕様書 4.6)。
   終えるときは、状態を保存し、音声の経路を片付ける。
6. 試作の画面のコード(`ContentView.swift`、`PrototypeModel.swift`)を片付ける。
   確認用の値(コールバックの回数など)は、ふだんの画面には出さない。
7. `README.md`(利用者向け)を作る。使い方だけを書く。

### 安全のための決まり

- 起動から加工が始まるまでの間は、元の音が最大音量で出る。この時間をできるだけ短くする。
- 画面の更新は、ポップアップを開いている間だけにする(試作では、0.5 秒ごとの書き直しがメインスレッドを約 4% 使った)。

## 実施結果

2026-10-12 に実施。利用者が、画面と音を確かめた。

行ったこと:

- メニューバー常駐にした(`MenuBarExtra`)。Dock にアイコンを出さない(`LSUIElement`)。
- アプリの状態の部品(`AppModel`)と、ポップアップ(`PopupView`)を作った。試作の画面のコードは消した。
- 起動すると、保存した状態を読み込み、加工を自動で始める。音量と消音は、出力先(装置の UID)ごとに覚えた値を使う。
- 音量と消音を変えると、0.5 秒後にまとめて保存する。終了時にも保存する。
- 読み込みの結果が「保存してはいけない」のときは、保存せず、理由をポップアップに出す。
- 終了と、「音声の加工」を切る操作の前に、音が最大音量に戻る注意を出して確かめる。
  加工していないときの終了は、確かめずに終える(音量が変わらないため)。
- 利用者向けの `README.md` を作った。
- 消音と音量から倍率を決める計算を、`Core/` にテスト先行で足した(失敗 → 実装 → 通過。3 件)。

手順からの変更点:

- 「音声の加工」は、スイッチではなく「切る」「入れる」のボタンにした。
  スイッチだと、確かめる画面で取り消したときに、表示だけが「切」に変わるおそれがあるため。
- 加工が止まっていないかの確かめは、ポップアップを開いている間ではなく、3 秒おきにいつも行う。
  止まったとき、加工を切っているとき、始められなかったときは、メニューバーのアイコンを警告の印に変える。
  常駐にすると、ふだんはポップアップを開かないので、開いている間だけの確かめでは気づけないため。
  確かめの中身は数値を1つ読むだけで、負荷はほとんどない。
- 確認用の値(コールバックの回数など)は、画面から外した。

見直し(`/code-review`)で見つかり、直したこと:

- 確かめる画面で取り消すと、スイッチの表示だけが変わるおそれがあった(上のとおり、ボタンにした)。
- 確かめる画面が、ほかのウィンドウの裏に隠れるおそれがあった(Dock に出ないアプリのため)。前面に出すようにした。
- 加工が止まっても、ポップアップを閉じていると気づけなかった(上のとおり、いつも確かめてアイコンで知らせる)。
- 保存に1回失敗すると、次に成功しても「保存できませんでした」が出続けた。成功したら消すようにした。
- スライダーの刻みが外れていて、音量が小数で保存されていた。1 刻みに戻した。
- 加工を始められなかったときにも、画面の音量が書き換わっていた。始められたあとで写すようにした。
- 値が変わらないのに書き込んで、画面を作り直していた。変わったときだけ書くようにした。

見直しで見つかり、直していないこと:

- 「システム音声の録音」の許可がないとき、加工は「動いている」と表示される見込み。
  許可の状態を確かめる方法が分からないため。何が起きるかを TICKET-006 の 12 で確かめてから、対処を決める。

確認できたこと(Claude):

- テストが通る(40 件と 27 件)。アプリのビルドが通る(警告なし)。
- できたアプリの設定に、Dock に出さない指定が入っている。
- 音声のスレッドで動くコードは、TICKET-003 から変えていない。

利用者が確かめたこと(2026-10-12):

- メニューバーにアイコンが出て、Dock には出ない。起動すると、何も押さなくても加工が始まる。
- スライダーで音量が変わる。消音で音が消え、戻る。
- 「音声の加工」を切るときに注意の画面が前面に出る。取り消すと加工が続く。
  切ると音が最大音量に戻り、アイコンが警告の印に変わる。入れ直すと戻る。
- 終了で注意の画面が出て、終えると音が元の経路に戻る。
- 起動し直すと、音量と消音が元に戻っている。
- チケットからの変更点と、直していない点(許可がないときの表示)は、利用者が了解した。
