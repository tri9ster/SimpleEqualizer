## 対応方針・作業手順

### `presets.json`

```json
{
  "version": 1,
  "presets": [
    { "id": "UUID", "name": "映画", "gainsDb": [0, 4.0, 3.0, 1.5, 0, 0, 1.0, 2.0, 2.5, 2.0] }
  ]
}
```

- 「フラット」は、ファイルに書かない(アプリが、いつも先頭に足す)。ファイルに「フラット」と同じ `id` や名前があっても、読まない。
- 保存先は `~/Library/Application Support/SimpleEqualizer/presets.json`。書き込みは、途中で壊れない方法(`state.json` と同じ)で行う。

### 読めないときの扱い(一覧の README の「壊れたファイルの扱い」)

| 場合 | 動き |
| --- | --- |
| ファイルがない | 「フラット」だけで始める。保存してよい |
| 全体が読めない(JSON として壊れている) | 別名(`presets.broken-<日時>.json`)で残し、「フラット」だけで始める |
| 新しい版のファイル、あるのに読めないファイル、別名にできなかった壊れたファイル | 「フラット」だけで始める。上書きしない |
| プリセットの一覧(`presets`)がない | プリセットのファイルではないものとして、全体が読めないときと同じに扱う(別名で残す) |
| 版の番号が、整数として読めない(小数、文字など) | 新しい版の書き方かもしれないので、触らない。上書きしない |
| 一部のプリセットだけが壊れている(値の個数が違う、範囲の外、名前が空、`id` が読めない、`id` や名前が重なっている) | そのプリセットは読まない。ほかは読む。読まなかった数を返す。読み込んだその場で、元のファイルの写しを別名(`presets.partial-<日時>.json`)で残し、読めた分で書き直す。写しを残せないときは、書き直さず、上書きもしない |

- 値は、近い端(+10 dB)に丸めない。壊れた値のプリセットは、まるごと読まない(`EqualizerSettings(storedGains:)` と同じ考え方)。
- 読めなかった理由は、`StateStore` と同じ形で返す(画面に出すため)。似た処理は、`StateStore` と共用にできるなら共用にする。

### `state.json` に足す項目

- `selectedPresetId`: 選んでいるプリセットの `id`。項目がない、読めない、一覧にない `id` のときは、「フラット」を選んでいるものとする。
- `equalizerGainsDb` は、これまでどおり「保存していない変更を含む、いまの値」として使う。
  起動時は、`selectedPresetId` のプリセットを選んだ状態で、値は `equalizerGainsDb` にする(違っていれば、変更の印がつく)。
- 版の番号は 1 のまま(項目を足すだけ)。段階3 のファイルは、そのまま読める(フラットを選び、値に違いがあれば変更の印がつく)。

### 書き出しと読み込みのファイル

- 形式は `presets.json` と同じ(版の番号と、プリセットの一覧)。拡張子は `.json`。
- 書き出し: 全部のプリセット(「フラット」を除く)を1つのファイルに書く。
- 読み込み: いまの一覧に足す。`id` は新しく振り直す(同じファイルを2回読み込んでも、ぶつからない)。
  名前が重なるときは、番号をつける(TICKET-001)。壊れたプリセットは読まず、読んだ数と読まなかった数を返す。
- 読み込むファイルが読めないとき、新しい版のときは、何も足さずに、理由を返す。

### 手順

1. 失敗するテストを先に書く。保存して読み戻せる、上の表の場合ごとの動き、`state.json` の項目、書き出しと読み込み。
2. 失敗することを確かめてから、実装する。
3. テストが通ることを確かめる。

## 実施結果

- テストを先に書き、実装の前に失敗することを確かめた。実装のあと、テストは 248 件(169 + 65 + 14)が通った。アプリのビルドも通った。
- アプリの動きは、1点を除いて変わらない(アプリは、プリセットをまだ使っていない)。
  変わる1点は、下の「`state.json` の扱いの変更」。
- このビルドで保存した `state.json` には、`selectedPresetId`(「フラット」の id)が入る。

### 作ったもの

- `PresetStore`: `presets.json` の読み書き、書き出しと読み込み。
- `VersionedFile`: 版の番号つきのファイルを読む共通の手順(あるか、読めるか、版が新しすぎないか、壊れていたら別名で残す)。
  `state.json` と `presets.json` の両方が使う。
- `AppState.selectedPresetID` と、`PresetLibrary.resolvedSelection`(一覧にない id は「フラット」)。

### チケットから変えたこと

- **一部が壊れたファイルの写しは、「次に保存する前」ではなく、読み込んだその場で残す。**
  あわせて、読めた分でファイルを書き直す。保存の側が「写しを残したか」を覚えておく必要がなくなり、起動のたびに写しが増えることもない。
- **読み込みで、名前が空のプリセットは、読まないのではなく、決まった名前(「プリセット」)にして読み込む。**
  値が使えるなら、捨てないほうがよい。値が壊れているものは読み込まない。

### `state.json` の扱いの変更(段階2 の動きを1つ変えた)

- 版の番号が整数として読めないファイル(小数、文字など)を、これまでは「壊れたファイル」として別名に移していた。
  新しい版の書き方かもしれないので、**触らず、上書きもしない**ことにした(`presets.json` と同じ)。
- 段階2 のテストのうち、この場合を「別名で残す」としていた1件を、新しい決まりに合わせて直した。
- アプリの画面では、「前回の設定を読めなかったので、音量 30 で始めました。元のファイルを守るため、今回の設定は保存しません」と出る。
