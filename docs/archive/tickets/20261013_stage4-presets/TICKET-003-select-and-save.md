# TICKET-003: 選択と保存の画面

## 概要

プリセットを、アプリの画面につなぐ。選んで呼び出す、変更の印を出す、「保存」「別名で保存」を作る。

## 対応方針・作業手順

### ポップアップ(仕様書 5.1)

- 「プリセット」の選択を足す。いま選んでいるプリセットの名前を出し、一覧から選べる。
- 保存していない変更があるときは、名前のあとに `*` をつける。

### イコライザーのウィンドウ(仕様書 5.2)

- 上に、プリセットの選択(ポップアップのものと連動)。変更があるときは `*`。
- 下に「保存」「別名で保存」を足す。「フラットに戻す」は残す。
  - 「保存」: 選んでいるプリセットを、いまの値で上書きする。変更がないとき、「フラット」を選んでいるときは押せない。
  - 「別名で保存」: 名前を入れる画面を出し、新しいプリセットとして保存して、それを選ぶ。
    使えない名前(空、長すぎる、同じ名前がある)のときは、理由を出して、入れ直してもらう。
- 「フラットに戻す」は、スライダーをすべて 0 dB にするだけで、選んでいるプリセットは変えない(変更の印がつく)。
  「フラット」のプリセットを選ぶのとは、別の操作である。

### 動き

- プリセットを選ぶと、10 バンドの値が、そのプリセットの値になり、すぐ音に反映する。
- 保存していない変更があるときに、別のプリセットを選んだら、確かめる画面を出す(一覧の README の「1」。利用者の判断による)。
- 選んでいるプリセットと、いまの値は、`state.json` に保存する。プリセットの一覧は、変えるたびに `presets.json` に保存する。
- 起動時に、プリセットの一覧を読み込む。読めなかったとき、読まなかったプリセットがあるときは、ポップアップに説明を出す。
- プリセットを切り替えた瞬間に、雑音が出ないかを確かめる(値が一度に変わる)。出る場合は、手を止めて相談する。

### チケットから足したこと

- **「変更を戻す」のボタン。** 保存していない変更を捨てて、選んでいるプリセットの値に戻す。
  同じプリセットを選び直しても戻らない(一覧は、同じものを選んでも何も起きない)ので、戻す手段がなかった。
  仕様書 5.2 にはないボタンなので、利用者に伝える。
- プリセットのファイルを読めなかった起動では、「保存」「別名で保存」を押せない(元のファイルを上書きしないため)。
  選んでいたプリセットの記録も、書き換えない。

### `/code-review` の指摘と対処

| 指摘 | 対処 |
| --- | --- |
| プリセットをファイルに書けなかったとき、気づきにくく、やり直す手段もない | その場で知らせる画面を出す。次にプリセットを変えたときと、終了のときに、もう一度保存を試す |

| プリセットのファイルを読めなかった起動で、覚えていた選択を「フラット」で上書きする | その起動では、選択の記録を書き換えない |
| 確かめる画面が、できない操作(「フラット」の「保存」など)を案内する | できる操作だけを案内する |
| 選んでいるプリセットの値に戻す手段がない | 「変更を戻す」を足した |
| プリセットの操作のあと、矢印キーが効かなくなる | 操作のあと、矢印キーを受け取れる状態に戻す |
| 上書きしてはいけない起動で、ボタンを押せなくしているだけで、処理の側は守っていない | 処理の側でも断る(理由を返す) |
| 設定を読めなかったときの説明が、アプリの側にあり、テストがない | `Core/` へ移し、テストを足した |
