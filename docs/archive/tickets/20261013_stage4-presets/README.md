# 段階4(プリセット) チケット一覧(2026-10-13)

仕様書 11章の段階4にあたる。イコライザーの設定(10 バンドの値)に名前をつけて保存し、あとから呼び出せるようにする。

## この段階でできるようになること

- いまのイコライザーの設定に、名前をつけて保存できる。
- 保存したプリセットを、ポップアップとイコライザーのウィンドウの一覧から選んで呼び出せる。
- プリセットの上書き、名前の変更、削除ができる。
- 最後に使っていたプリセットが、次の起動で元に戻る。
- プリセットを1つのファイルに書き出し、読み込める(バックアップ用)。

出力先に合わせた設定(「SONOS 用」「内蔵スピーカー用」など)は、利用者がプリセットを切り替えて使う(仕様書 4.5)。
ただし、内蔵スピーカーなど、ほかの出力先の音を加工できるようになるのは段階5 である。
この段階のあいだ、プリセットが効くのは USB SPDIF Adapter に出ている音だけ。

## 範囲に入れないもの

- 音量キー、出力先との連動(いまの出力先を加工する)、設定のウィンドウ、ログイン時の起動。段階5。
- プリセットに含めないもの: 音量、消音、ラウドネスの強さ、イコライザーの入・切。
  これらは「前回の状態」として、プリセットとは別に保存する(仕様書 4.3)。

## 作業順序

```
TICKET-001 プリセットの型と、一覧の操作(テスト先行)
    └─ TICKET-002 保存と読み込み(presets.json、選択中のプリセット、書き出しの形式)
           └─ TICKET-003 選択と保存の画面(ポップアップ、イコライザーのウィンドウ)
                  └─ TICKET-004 名前の変更と削除
                         └─ TICKET-005 書き出しと読み込み
                                └─ TICKET-006 実機での確認とまとめ
```

- 001 と 002 を先にする理由: 音を出さずに確かめられる部分で、テストを先に書いて作る。
  利用者が作りためる設定を扱うので、「消えない」「壊れたときに救える」ことを、画面より先に固める。
- 003〜005 を分ける理由: 1件ごとに、画面を確かめてもらう量を小さくする。

## 着手前に利用者に決めてもらうこと

仕様書に書いていない動きが5つあった。2026-10-13 に、利用者が、5つとも提案のとおりに決めた。

| 番号 | 決めること | 決定(Claude の提案のとおり) |
| --- | --- | --- |
| 1 | 保存していない変更があるときに、別のプリセットを選んだら | **確かめる画面を出す**(「変更を捨てて切り替える」「キャンセル」)。変更がないときは、すぐ切り替える |
| 2 | 同じ名前のプリセットを作れるか | **作れない。** 同じ名前で保存しようとしたら、その旨を出して、名前を直してもらう |
| 3 | 「書き出し」は、どのプリセットを書き出すか | **全部を1つのファイルに。**(バックアップ用なので) |
| 4 | 「読み込み」は、いまの一覧をどうするか | **いまの一覧に足す。** 置き換えない。同じ名前があるときは、読み込む側の名前に番号をつける(「映画 2」) |
| 5 | はじめから用意するプリセット | **「フラット」だけ。** ほかの見本(低音強調など)は入れない |

### 補足

- 1: ポップアップからすばやく切り替えたいときに、確かめる画面はひと手間になる。
  ただ、確かめずに切り替えると、調整した値が、気づかないうちに消える。変更があるときだけなので、出す回数は多くない。
  わずらわしければ、「確かめずに切り替える」に変えられる。
- 「フラット」は、削除、上書き、名前の変更ができない。フラットを選んでスライダーを動かしたときは、
  「別名で保存」で新しいプリセットにする(「保存」は押せない)。
- 名前は、前後の空白を取り、空の名前は受けつけない。長さは 30 文字までとする。

## 壊れたファイルの扱い(Claude の提案。決めてもらうことではないが、知っておいてほしいこと)

利用者が作りためた設定なので、アプリが黙って消すことがないようにする。

- `presets.json` 全体が読めないとき: `state.json` と同じく、別名(`presets.broken-<日時>.json`)で残し、「フラット」だけで始める。
- 一部のプリセットだけが壊れているとき(値の個数が違う、範囲の外など): そのプリセットは一覧に出さない。
  ほかのプリセットは使える。読み込んだその場で、元のファイルの写しを別名(`presets.partial-<日時>.json`)で残す(壊れた1件を、上書きで消さない)。
- 新しい版のアプリが作ったファイル、あるのに読めないファイルは、上書きしない(`state.json` と同じ)。

## 音を出すときの安全(この段階での変更点)

- プリセットを呼び出すと、10 バンドの値が一度に変わる。増幅の大きいプリセットに切り替えると、音が大きくなる。
  リミッターがあるので、元の信号の上限は超えない(段階3 と同じ)。
- 起動時には、最後に使っていたプリセットと、保存していない変更を含む値で始まる(段階3 と同じ値。新しく上がるものはない)。
- 読み込んだプリセットは、選ぶまで音に反映しない。読み込んだだけで、音が変わることはない。
- 値が範囲の外のプリセット(手で書き換えたファイルなど)は、読み込まない(近い端の +10 dB に丸めない)。
- 音を試す直前には、毎回、スピーカー側の音量を下げてもらう。
