## 現状

2026-11-08 時点。

- ホームページはない。利用者向けの説明は、README(英語の `README.md`、日本語の `README.ja.md`)だけ。
- `origin` は非公開のリポジトリ。公開するときは、履歴のない新しいリポジトリにする(配布の TICKET-001、TICKET-009)。
- `docs/` は開発の記録に使っている。GitHub Pages の「ブランチから公開」で選べる場所は、直下か `docs/` だけ。
- アイコンの元データは `design/AppIcon.svg`、`design/MenuBarIcon.svg`(利用者が置くもの。Claude は読むだけ)。

## 対応方針・作業手順

1. 次を決めて、利用者に見せる。Claude の案:
   - 作り方: 手書きの HTML と CSS(外部のライブラリやテーマを使わない)。1ページで足りる量なので、Jekyll は使わない。
   - 置き場所: `site/`。公開は GitHub Actions(`actions/upload-pages-artifact`、`actions/deploy-pages`)。
   - 言語: 英語を `site/index.html`、日本語を `site/ja/index.html` にし、ページの先頭で互いに案内する(README と同じ形)。
   - 載せる内容(上から):
     1. アプリの名前、アイコン、ひとこと説明、ダウンロードのボタン(`releases/latest` へのリンク)
     2. 何ができるか(音量、消音、音量キー、10 バンドのイコライザー、ラウドネス、プリセット)と、画面の画像
     3. 動く環境(macOS 27 以降、Apple シリコンの Mac)
     4. 使う前に(スピーカー側の音量を下げる)
     5. 入れ方と、初めて開くときの操作(公証を受けていないため)、許可
     6. ソース(GitHub のリポジトリ)と利用許諾(MIT)
   - 細かい使い方は、ページに写さず README へ案内する(同じ内容を3か所で直さずに済むように)。
   - ダークモードに合わせる。スマートフォンの幅でも崩れないようにする。
   - 外に送るもの(アクセス解析、外部のフォント)は使わない。
2. 利用者の確認を受けてから、仕様書の 7.1(配布)と変更履歴に書く。
