## 対応方針・作業手順

1. ブランチを作る(例: `feat/homepage`)。
2. 次のファイルを作る。
   - `site/index.html`(英語)、`site/ja/index.html`(日本語)
   - `site/style.css`(両方で使う。ダークモードとスマートフォンの幅に対応)
   - `site/images/`: アイコンは `design/AppIcon.svg` を写して使う(`design/` は書き換えない)。画面の画像は TICKET-002 でそろうまで仮の枠にする。
3. 文言は README と食い違わないようにする。画面の項目名は、文字列カタログの値(英語、日本語)に合わせる。
4. 機材の名前を書いていないことを、`grep` で確かめる。
5. 利用者に、ブラウザで `site/index.html` と `site/ja/index.html` を開いて、見た目を確かめてもらう(ライトとダーク、ウィンドウを狭くしたとき)。

## 影響ファイル

- `docs/architecture.md`(ページの置き場所と作り方)、`docs/dev-log.md`

## 実施結果

2026-11-08 に作り、利用者が確かめた。

- 作ったもの: `site/index.html`(英語)、`site/ja/index.html`(日本語)、`site/style.css`、`tools/build-site.sh`。
- 画像は `site/images/` に写す予定だったが、README の画像(`assets/`)をそのまま使うように変えた。
  `tools/build-site.sh` が、公開するときに `assets/` を入れる。README と同じ画像を2か所で持たずに済む。
- 画面の画像は、利用者が README 用に撮ったもの(`assets/main_window.png`。英語の画面)を、日本語のページでも使う(README と同じ)。
  そのため、TICKET-002 で新しく撮る必要は、ほぼなくなった。
- Claude が確かめたこと: ヘッドレスの Chrome で撮った画面で、幅 1280 と幅 500 の表示(ダークモード)。
  日本語のページで、HTML の改行が空白として出ていたので、本文の途中の改行を詰めた。
  冒頭の文が語の途中で折り返していたので、`word-break: auto-phrase` をつけた。
- `/code-review` の指摘で直したこと: `tools/build-site.sh` が消してよい出力先を `build/site` と `_site` に限った。
  暗い表示のダウンロードのボタンの文字が読みにくかった(背景をリンクの色にしていた)ので、ボタンの色を分けた。
  二つ目のボタンに、ポインターを載せたときの変化をつけた。`hreflang` を完全なアドレスにし、自分のページも並べた。
  直さなかったこと(README の画像が、このブランチにないこと、「Applications」と「アプリケーション」)は `TODO.md`。
- 利用者が確かめたこと: ライトモード、スマートフォンの幅、Safari での見た目(2026-11-08)。
  ヘッドレスの Chrome は、幅 500 より狭くできなかったので、狭い幅は利用者だけが確かめた。
- はまりどころ: README の画像の作業(`assets/main_window.png`、`assets/readme/app-icon.svg` など)が、
