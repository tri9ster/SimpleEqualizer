# TICKET-003: いまの出力先を加工する

## 概要

加工の対象を、名前で決めた1つの装置から、macOS のいまの出力先に変える。出力先が変わったら、加工の対象も切り替える(仕様書 4.5)。
段階5 で、いちばん大きく、音の安全に関わる作業である。

## 対応方針・作業手順

### 作るもの

- いまの出力先を調べ、その出力先で経路を作る。対象を、名前ではなく、装置そのもの(UID)で決める。
- 出力先が変わった知らせを受けたら、いまの経路を片付け、新しい出力先で経路を作り直す。
  抜き差し、スリープからの復帰も、同じ流れで扱う。
- 扱えない出力先(TICKET-002 の判断)では、音声に触らず、理由をポップアップに出す。メニューバーのアイコンは、警告の印にしない
  (音量を macOS で変えられる出力先なら、危なくない)。音量を変えられない出力先で扱えないときは、警告の印にする。
- 入力と出力が1本ずつでない装置の扱い(`docs/TODO.md`)を、ここで決める。

### 切り替えた瞬間の音(2026-10-14 に、利用者が案A に決めた。下の表の案2 にあたる)

- 音量を変えられない装置(USB SPDIF Adapter、ディスプレイ)の経路は、つながっている間、持ったままにする。
  出力先でないあいだも動かしておくので、戻した瞬間に切れ目がない(調査で、いまの作りがそうなっていることを確かめた)。
- 音量を変えられる装置(内蔵スピーカー)の経路は、出力先になったときだけ作る。作る間の 0.15 秒ほどは、加工なしの音が出るが、
  macOS の音量が効いているので、危なくない。
- 負荷は、作ってから測る。CPU 使用率が 3% を超えるようなら、利用者に相談する。

決める前に考えたこと:

経路を作り直す間、切り替え先の音が、加工なしで出るおそれがある。USB SPDIF Adapter へ戻したときが危ない。
TICKET-001 で測った時間を見て、次のどれにするかを、利用者に示して決めてもらう。

| 案 | 内容 |
| --- | --- |
| 案1 | 作り直すだけ。かかる時間が、聞こえないほど短い場合 |
| 案2 | 音量調整が有効な出力先(USB SPDIF Adapter など)の経路は、切り替えたあとも残しておく(いまの動きに近い)。戻したときに、すぐ加工が続く |
| 案3 | そのほか、調査で見つかった方法 |

### 安全のための決まり

- 作り直しに失敗したときは、音声に触らず、メニューバーのアイコンを警告の印にする(段階2 の動きのまま)。
- 短い間に何度も切り替えられても、経路を二重に作らない。
- 加工を始めるときは、これまでどおり、倍率を 0 からなめらかに上げる。

## 実施結果

2026-10-14 に実装した。利用者の確認は、まだ(未確認)。

### 作ったもの

- 出力先の情報を読む部分と、変化の知らせを受ける部分(`SimpleEqualizer/OutputDevices.swift`)。
- 経路を、出力先ごとに持つ形にした(`AppModel`)。案A のとおり。
  - いまの出力先と、音量を変えられない出力先の全部(扱える形のもの)に、経路を持つ。
  - 音量を変えられる出力先(内蔵スピーカー)の経路は、いまの出力先でなくなったら、片付ける。
  - (取りやめ)装置が抜かれても、経路は片付けない。差し直すと、音を取り出せなくなることが分かったので、
    抜かれたら片付け、差し直されたら作り直す形にした(下の「コミットのあとで見つかった不具合(2)」)。
  - (取りやめ)装置があるのに、9 秒ほどコールバックが呼ばれていない経路は、作り直す。スリープの間に、動いていた経路を壊したので、取り除いた(下の「コミットのあとで見つかった不具合」)。
- 出力先が変わると、画面の音量と消音が、その出力先について覚えているものに変わる。ポップアップに、いまの出力先の名前を出す。
- イコライザーは、全部の経路に同じ値を掛ける。音量、消音、ラウドネスの補正量は、出力先ごとに決める。
- 扱えない出力先では、音声に触らず、理由をポップアップに出す。メニューバーのアイコンを警告の印にするのは、
  その出力先が、音量を変えられないもののときだけ。
- 入力と出力が1本ずつでない装置は、これまでどおり、扱わない(確かめる対象の3つの出力先は、どれも1本ずつだった)。

### TICKET-004 から、先に入れたもの

経路を出力先ごとに持つと、音量調整が無効の出力先(内蔵スピーカー)でも加工が始まる。そのままでは動きが半端になるので、
次の3つを、ここで入れた。画面の作り込みと、自動で下げる設定の切り替えは、TICKET-004 に残してある。

- 音量調整が無効の出力先では、倍率を、覚えている音量ではなく、「増幅した分を自動で下げる量」で決める(TICKET-002 の判断を使う)。
- 音量調整が無効の出力先では、ポップアップの音量、消音、ラウドネスを使えなくし、「この出力先の音量は、macOS の音量で変えます」と出す。
- 音量調整が無効の出力先では、音量キーに触らず、macOS に任せる。

### 確認の途中で見つかったこと(2026-10-14)

- 利用者の報告: 出力先を USB SPDIF Adapter に切り替えるたびに、「音量が大きいため、音を抑えています」と出る。
  ディスプレイのスピーカーに切り替えたときにも、出ることがある。
- 原因: 表示の判断が、別の経路の回数と比べていた(Claude の見落とし)。実際にリミッターが働いたわけではない。
  くわしくは `docs/failures.md` の 2026-10-14。
- 対処: 表示の判断を `Core/` の `LimiterIndicator` に移し、出力先が変わったら比べ直すようにした。テストを先に書いた。
- 記録(`research-log.txt`)から分かったこと:

  - 切り替えを続けて行っても、経路の作り直しは起きなかった(USB SPDIF Adapter とディスプレイの経路は、持ったままだった)。
  - CPU 使用率(アプリ全体。30 秒の平均): 経路 2 本で 3.0〜8.2%、経路 3 本で 3.9〜7.5%。
    ウィンドウを開いて操作している間の値を含む。静かに再生している間は、3.0〜3.5% だった。目標(3% 以下)を、少し超えている。

    AirPlay は、確かめる対象に入れていない。どう聞こえたかを、利用者に聞く。

### コミットのあとで見つかった不具合(2): ケーブルを差し直すと、加工なしの音が出る(2026-10-14)

- 利用者の報告: ケーブルを抜いて差し直すと、加工なしの音が出る。画面は、加工中の表示のまま。
  ケーブルの抜き差しは、ふだん行わない操作なので、直すのに手間がかかるなら、課題として残すだけでもよい、とのこと。
- 原因: 経路の様子を記録に書くようにして、調べた。差し直すと、装置の番号が変わり、音を取り出す口(タップ)が、
  差し直した装置の音を取り出さなくなる。コールバックは呼ばれ続けるので、「止まっている」とは判断されない。
  くわしくは `docs/failures.md` の 2026-10-14。
- 対処: 装置が抜かれたら、その経路を片付け、差し直されたら、新しく作る。変更は、小さい(片付ける条件を変えただけ)。
  上の「作ったもの」のうち、「装置が抜かれても、経路は片付けない」は、取りやめた。
- 利用者の確認(2026-10-14): 直したアプリで、ケーブルの抜き差し(2回)、出力先の切り替え、スリープと復帰を頼み、
  「完璧」との返事と、コミットの指示を受けた。
- 記録(`research-log.txt`)で、Claude が確かめたこと:
  - ケーブルを抜くと、経路が片付けられ、差し直すと、新しく作られた(2回とも)。差し直したあと、取り出した音の大きさは 0.2〜0.3 で、音を取り出せていた。
  - スリープから復帰したあと、ディスプレイの装置の番号が変わっていて(86 → 176)、その経路が、自動で作り直された。
    ケーブルの差し直しと同じことが、スリープからの復帰でも起きうることが分かった。今回の直し方で、あわせて直っている。
- コミットの前の `/code-review` で、さらに直したこと(起きにくい場合への対処。利用者は、確かめていない):

  | 指摘 | 対処 |
