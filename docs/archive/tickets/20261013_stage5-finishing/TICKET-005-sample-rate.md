## 実施結果

2026-10-15 に、原因を突き止めて直した。くわしくは `docs/failures.md` の 2026-10-15。

- 再現: 利用者が、「Audio MIDI 設定」で USB SPDIF Adapter の周波数を 44,100 Hz に変えると、音がとぎれた。48,000 Hz に戻すと直った。
- 原因: 経路(エンジン、リミッター)が、作ったときの周波数のまま動いていた。44,100 Hz のあいだは、取り出した音が、
  ところどころ無音になっていた(記録で確かめた)。
- 対処: 周波数の変化の知らせを受けたら、経路を作り直す。
- 1回目の直し方(片付けてから作る)で、利用者が確かめた(2026-10-15): 44,100 Hz でも、とぎれない。48,000 Hz に戻しても、問題ない。
  44,100 Hz で、イコライザーの効き方もいつもどおり。「バッチリです」との返事を受けた。
  記録でも、作り直したあと、取り出した音の大きさが 0 にならなくなった。
- コミットの前の `/code-review` で、作り直す間(記録では 0.7 秒ほど)、元の音が加工なしで出ることを指摘された。
  新しい経路を先に作ってから、前の経路を片付ける形に変えた。利用者が、周波数の切り替えを2〜3回くり返して確かめ、コミットの指示を受けた。
  記録でも、切り替えのたびに経路が作り直され、そのあと音を取り出せていた。作り直しには、0.7 秒ほどかかっていた(ふだんは 0.07 秒)。
- コミットの前の2回目の `/code-review` で、さらに直した。**この分は、利用者は、まだ確かめていない(未確認)。**
  - 前の経路の音を先に消してから、新しい経路を作る(2つの経路の音が重なって、元の大きさを超えないように)。作り直す間は、無音になる。
  - 作り直し方を1つにまとめた。知らせを取りこぼした場合(スリープの間に変わった、など)も、同じ作り直し方になる。
  - 周波数を読む前から、知らせを受ける。経路を作っている間に周波数が変わっていたら、作り終えたあとに合わせ直す。

`/code-review` の指摘と対処:

| 指摘 | 対処 |
| --- | --- |
| 作り直す間、元の音が、加工なしの元の大きさで出る | 新しい経路を先に作ってから、前の経路を片付ける。新しい経路を作れなかったときは、前の経路を残す |
| 作り直しに失敗したときに、すぐやり直す回数が残っていないことがある | 新しい経路を作れなかったときは、前の経路を残すので、加工なしにはならない |
| 出力装置の周波数を読めなかったとき、代わりの値と比べて、作り直しを繰り返す | 読めなかったときは、比べない |
| 説明のコメントの位置の誤り、同じ読み取りの重複、止めたあとに古い周波数が残る | 直した |
