## 対応方針・作業手順

### 判断するもの

入力は、出力先の情報(装置が自分で音量を変えられるか、チャンネル数、ストリームの本数、形式など)。出力は、次の判断。

| 判断 | 決まり |
| --- | --- |
| 音量調整が有効か | 装置が自分で音量を変えられないとき、有効。**見分けられないときは、有効として扱う**(音量を変えられない装置から、最大音量が出るのを防ぐ) |
| ラウドネスを使えるか | 音量調整が有効のときだけ(仕様書 4.3) |
| 扱える出力先か | 確かめてある形だけ。扱えないときは、音声に触らず、理由を出す(仕様書 4.5) |
| 増幅した分の自動の引き下げ | 音量調整が無効で、自動で下げる設定が入で、上げているバンドがあるとき(一覧の README の「1」) |

- 音量と消音は、出力先(UID)ごとに覚える(段階2 で作ってある)。音量調整が無効の出力先では、覚えた値を使わず、倍率は 1 にする。
- 増幅した分の引き下げの量は、`EqualizerSettings` から求める(いちばん大きく上げているバンドの量。上げていなければ 0)。
  イコライザーが切のときは 0。

  - 音量調整が有効か(見分けられないときは、有効)。出力先でないあいだも経路を持ったままにするか(案A)。ラウドネスを使えるか。

### 着手後に分かったこと: 自動で下げる量は、「いちばん大きく上げているバンドの量」では足りない

- `/code-review` の指摘を受けて、本物のエンジンで測った(音は出ない)。となり合うバンドを上げると、山が重なって、
  合わせた増幅が、1つのバンドの量より大きくなる。

  | 設定 | 測った、いちばん大きい増幅 |
  | --- | --- |
  | 1 kHz だけ +10 dB | +9.8 dB |
  | 1 kHz と 2 kHz を +10 dB | +12.0 dB |
  | 1 kHz、2 kHz、4 kHz を +10 dB | +13.9 dB |
  | 全部のバンドを +10 dB | +15.5 dB |
  | 1 kHz を +10 dB、2 kHz を −10 dB | +8.0 dB |

- そこで、下げる量は、「いちばん大きく上げているバンドの量」ではなく、**山の重なりを含めた見積もり**にした。
  1つとなりのバンドは約 2 割、2つとなりは約 0.75 割が重なる(いちばん高い2つのバンドは、約 3 割)。
  17 通りの設定で、測った値と見積もりを比べ、ずれは 1 dB 未満だった。エンジンのテストが、この比べ方を続ける。
- 利用者に示した説明(「いちばん大きく上げているバンドが +6 dB なら、全体を 6 dB 下げる」)は、
  1つのバンドだけを上げているときには、そのとおり。となりも上げているときは、それより多く下げる。報告のときに伝える。

### `/code-review` の指摘と対処

| 指摘 | 対処 |
| --- | --- |
| 下げる量が、バンドの山の重なりを見ていない | 測って、重なりを含めた見積もりにした(上) |
| 下げる量が壊れた値(無限大)のとき、下げない側(いちばん大きい音)に倒れる | 音を出さない側に倒す。テストを足した |
| 扱えない理由が、画面に出す文そのものになっている | 理由を種類で返し、文は別に持つ |
| 見分けられない装置(nil)の場合が、倍率、ラウドネス、音量キーで確かめられていない | テストを足した |
| 音量調整が無効の装置では、覚えている消音を使わない。見分けが途中で変わると、消音していた音が出る | 直さない。見分けは、装置をつないだときに1回だけ行う形にする(TICKET-003)。`docs/TODO.md` に書いた |
| 音量調整が有効の装置では、音量 100 で増幅すると、自動で下げずに、リミッターに任せる | 直さない。仕様のとおり(仕様書 4.2) |
| 自動で下げる設定が読めないとき「入」にするのは、イコライザーの入・切(読めないときは切)と逆 | 直さない。どちらも、音が小さくなる側に倒している |
