## 対応方針・作業手順

### 設定のウィンドウ(仕様書 5.3)

- いまの出力先と、音量調整が有効かどうかの表示(自動で決まるので、切り替えはない)。
- 音量キーを使うかどうか(初期値は有効)。「アクセシビリティ」の許可の状態。
- ログイン時に起動するかどうか(初期値は無効)。
- 増幅した分を自動で下げるかどうか(初期値は入。TICKET-004 で作った設定を、ここにも出す)。
- 「システム音声の録音」の許可について。この許可の状態は、アプリから調べられない(仕様書 8.1)。
  「許可済み」とは出さず、音を取り出せているか(状況からの判断)と、設定を開くボタンを出す。
- ポップアップに「設定…」を足す。

### ログイン時の起動

- macOS の標準の仕組み(`SMAppService`)で登録する(仕様書 7章)。
- 登録できなかったときは、理由を出す。いまの状態(登録されているか)を、設定のウィンドウに出す。
- 開発中のアプリ(`DerivedData` の中)を登録すると、ビルドし直したあとの動きがどうなるかを、着手時に確かめる。

### 保存

- 音量キーを使うかどうかは、`state.json` に足す(項目を足すだけ。版の番号は 1 のまま)。テストを先に書く。
- ログイン時の起動は、macOS の側が覚えるので、`state.json` には書かない。

### 作ったもの

- 設定のウィンドウ(`SimpleEqualizer/SettingsWindow.swift`)。ポップアップの「設定…」で開く。
  - 出力先: いまの出力先、アプリの音量調整が有効か、自動で下げる設定。
  - 音量キー: 使うかどうか(初期値は入)、「アクセシビリティ」の許可の状態。
  - 起動: ログイン時に起動するかどうか。
  - システム音声の録音: 音を取り出せているか(許可の状態は調べられないので、状況から判断している、と書いた)。設定を開くボタン。
- ログイン時の起動(`SimpleEqualizer/LoginItem.swift`)。macOS の標準の仕組み(`SMAppService`)で登録する。
  登録の状態は macOS が覚えているので、`state.json` には書かない。
- 音量キーを使う設定(`AppState.volumeKeysEnabled`)。テストを先に書いた。切にすると、キーの受け取りを外し、macOS に任せる。
  入にしたときに許可がなければ、許可を求める。

### 確かめていないこと

- ログイン時の起動は、`DerivedData` の中のアプリ(外付けのドライブの上)を登録する。
  利用者が、ログインし直して起動することを確かめた。外付けのドライブのつながり方によっては起動できない場合があるかもしれないが、
  今回は問題なかった。ふだん使うアプリの置き場所は、TICKET-008 で決める。

### `/code-review` の指摘と対処

| 指摘 | 対処 |
| --- | --- |
| 音量キーを入にしても、許可を求めない | 入にしたときに許可がなければ、求める |
| 音量キーを切にしても、キーの受け取りが残る | 切にしたら外す |
| ログイン項目が「見つからない」と返すと、切り替えを押せない(登録する前は、そう返されることがある) | 押せるようにし、登録できなかったら理由を出す |
| 出力先がないときに、「有効」と説明する | 出力先がないことを出す |
| 音量キーを切にしているのに、許可がないと出す | 切にしているときは、そう出す |
| ログイン項目の登録を、メインスレッドで行っている | 直さない。押したときの1回だけで、すぐ終わる見込み |
| 設定のウィンドウに、SwiftUI の標準の設定の画面を使っていない | 直さない。メニューバー常駐のアプリでは、イコライザーのウィンドウと同じ作りのほうが、確かに前面に出せる |
