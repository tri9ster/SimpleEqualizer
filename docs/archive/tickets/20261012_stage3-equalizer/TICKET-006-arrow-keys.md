# TICKET-006: 矢印キーでの操作

## 概要

イコライザーのウィンドウを、矢印キーで操作できるようにする(仕様書 4.2)。

## 対応方針・作業手順

### 動き

- 左右の矢印: 調整するバンドを選ぶ。端では止まる(反対の端へ回り込まない)。
- 上下の矢印: 選んでいるバンドを 0.5 dB ずつ増減する。Shift を押しながらだと 2 dB ずつ増減する。
  範囲(−10〜+10 dB)の端では止まる。
- 選んでいるバンドは、枠や色で分かるように表示する。
- ウィンドウを開いた直後は、いちばん左(31 Hz)を選んだ状態にする。
- スライダーをマウスで触ったときは、そのバンドを選んだ状態にする。

### 作り方

- 増減の計算(範囲に収める、刻みに合わせる)は、TICKET-002 の `EqualizerSettings` を使う。画面の側には計算を書かない。
- バンドを選ぶ計算(端で止まる)も、音を出さずに確かめられるので、`Core/` に置いてテストを先に書く。
- キーの受け取り方は、SwiftUI の標準の仕組みで行う。標準のスライダーが矢印キーを先に受け取ってしまう場合は、
  着手時に小さく試してから、受け取り方を決める。

### 作ったもの

- 左右の矢印でバンドを選び、上下の矢印で 0.5 dB ずつ、Shift + 上下で 2 dB ずつ変える。どちらも端で止まる。
- 選んでいるバンドは、列に色と枠をつけ、周波数の文字を太くして示す。
- ウィンドウを開いた直後(開き直したときも)は、いちばん左(31 Hz)を選ぶ。
- スライダーのつまみを引き始めたとき、列を押したときは、そのバンドを選ぶ。押しただけでは、値は変わらない。
- バンドを選ぶ計算(端で止まる)と、キーで動かす量(上下、Shift)は、`Core/` の `EqualizerSettings` に置き、テストを先に書いた。
- キーの受け取りは、SwiftUI の標準の仕組み(`onKeyPress`)で行った。スライダーは自分で作ったものなので、
  標準のスライダーが矢印キーを先に受け取る問題は起きない。

### `/code-review` の指摘と対処

| 指摘 | 対処 |
| --- | --- |
| 開いた直後は、ウィンドウがまだ手前に出ておらず、キーを受け取る設定が効かないおそれ | 設定を3か所で行う形にした(開くときの指定、表示されたとき、0.2 秒後)。効くかは、利用者の確認で確かめる |
| 開き直したときに、前に選んでいたバンドが残る | 表示されたときに、いちばん左へ戻す |
| Shift 以外の修飾キー(Command など)との組み合わせも、値の変更として扱っていた | 扱わないようにした |
| 読み上げ(VoiceOver)の増減の操作で、読み上げの位置がスライダーから外れる | その操作のときは、キーを受け取る場所を動かさない |
| 「選んでいる」ことが、読み上げで伝わる場所についていない | スライダーの要素につけた |
| ボタンなどに操作の場所が移ると、戻す手段がスライダーを押すことしかない | ウィンドウの余白を押しても戻るようにした |
| つまみを引いている間、毎回バンドを選び直していた | 引き始めの1回だけにした |
| Shift で 2 dB 動くことが、テストで守られていない | 動かす量を決める関数を `Core/` に置き、テストを足した |
| バンドを選ぶ計算が、必要以上に複雑(大きな数のあふれ対策) | 直さない。害はなく、テストもある |
