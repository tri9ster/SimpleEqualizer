# 段階3(イコライザー) チケット一覧(2026-10-12)

仕様書 11章の段階3にあたる。段階2 の経路(タップ → 音量 → 出力)に、
10 バンドのイコライザー、ラウドネス、リミッターを足す。

## この段階でできるようになること

- イコライザーのウィンドウで、10 バンド(31 Hz〜16 kHz)を −10〜+10 dB の範囲で調整できる。矢印キーでも操作できる。
- メニューバーのポップアップで、イコライザーとラウドネスを、それぞれ入・切できる。
- 増幅しても音が割れないよう、出力の直前でリミッターが上限を超えた分を抑える。
- イコライザーの設定(10 バンドの値、入・切)とラウドネスの入・切が保存され、次の起動で元に戻る。

## 範囲に入れないもの

- プリセット(名前をつけて保存、呼び出し、書き出しと読み込み)。段階4。
  イコライザーのウィンドウには、この段階では「フラットに戻す」だけを置く。
  いまの 10 バンドの値は、「前回の状態」として1組だけ保存する。
- 音量キー、出力先との連動、設定のウィンドウ、ログイン時の起動。段階5。
- サンプリング周波数の切り替えで音がとぎれる課題。段階5。

## 作業順序

```
TICKET-001 リミッター(C、テスト先行)
TICKET-002 イコライザーの設定とラウドネスの補正量、状態の保存(テスト先行)
    └─ TICKET-003 コールバックからエンジンを呼ぶ(イコライザーはすべて 0 dB)
           └─ TICKET-004 イコライザーのウィンドウと、ポップアップの入・切
                  └─ TICKET-005 ラウドネス
                         └─ TICKET-006 矢印キーでの操作
                                └─ TICKET-007 実機での確認とまとめ
```

- 001 を最初にする理由: 増幅する機能(イコライザー、ラウドネス)を入れる前に、音が割れない仕組みを先に入れる。
  音を出さずに確かめられる部分なので、テストを先に書いて作る。
- 002 を 003 の前にする理由: 音を出さずに確かめられる部分(値の範囲、補正量の計算、保存)を先に固める。
- 003 と 004 を分ける理由: 段階2 と同じ。経路と画面を同時に替えると、不具合のときに原因を切り分けにくい。
  003 では、イコライザーをすべて 0 dB のまま通し、「音が変わらないこと」だけを確かめる。
- 005 を 004 のあとにする理由: ラウドネスは、イコライザーと同じ仕組み(エンジンの中のフィルター)を使う。
  イコライザーで仕組みが動くことを確かめてから、補正量を聴いて決める。

### 1 の補足: リミッターを C で書く

- 仕様書 7章の順序は「イコライザー → ラウドネス → 音量 → リミッター」。音量は、いま C のコールバックが掛けている。
  リミッターをその後ろに置くには、リミッターも C の側に置くのが素直である。
- 作るのは、「上限を超えそうな瞬間だけ全体の倍率を下げ、そのあとゆっくり戻す」という小さな処理(数十行)。
  外部ライブラリは使わない。
- 利点: 音を出さずに、自動テストで「どんな入力でも出力が上限を超えない」ことを確かめられる。
- 比べた案: macOS に入っているリミッターの部品をエンジンの中に置く。
  この場合、音量もエンジンの中へ移す必要があり、段階2 で確かめた「なめらかな音量の変化」を作り直すことになる。採らない。

### 2 の補足: 音量調整が無効の出力先での増幅

- 音量調整が無効の出力先(内蔵スピーカーなど)は、いつも元の音量なので、イコライザーで増幅すると、いつもリミッターが働く。
  リミッターが働き続けると、音がつぶれて聞こえる。
- 提案: **増幅した分だけ、全体を自動で下げる。** たとえば最大で +6 dB 上げているバンドがあれば、全体を 6 dB 下げる。
  音はつぶれないが、イコライザーを入れると全体が少し小さくなる。小さくなった分は、macOS の音量調整で上げてもらう。
- 段階3 のあいだは、対象が USB SPDIF Adapter だけ(音量調整はいつも有効)なので、この動きを使う場面がない。
  方針だけ決めて、作るのは、ほかの出力先を扱う段階5 にする。
- 音量調整が有効の出力先(USB SPDIF Adapter)では、仕様書のとおり、何もしない。
  音量を下げている間は増幅しても上限を超えず、リミッターが働くのは音量が 100 に近いときだけである。
  **音量 100 のままイコライザーで増幅すると、リミッターが働いて音がつぶれることがある。**
  TICKET-004 で、リミッターが働いていることをイコライザーのウィンドウに表示する。

### 3 の補足: ラウドネスの補正量(仮)

音量を下げた量(dB)に比例して補正を増やし、40 dB 下げたところで上限に達する形を、仮の式とする。

| 音量 | 音量による減衰 | 低音の補正 | 高音の補正 |
| --- | --- | --- | --- |
| 100 | 0 dB | 0 dB | 0 dB |
| 70 | −9.3 dB | +1.9 dB | +0.7 dB |
| 50 | −18.1 dB | +3.6 dB | +1.4 dB |
| 30 | −31.4 dB | +6.3 dB | +2.4 dB |
| 22 以下 | −40 dB 以下 | +8.0 dB(上限) | +3.0 dB(上限) |

- 上限(低音 +8 dB、高音 +3 dB)は、仕様書 4.3 の仮の値。
- 補正は、いつも音量による減衰より小さい。ラウドネスだけで、音が元の音量を超えることはない。
- 持ち上げる範囲は、低音が 100 Hz より下、高音が 8 kHz より上を仮の値とする。
- TICKET-005 で実際に聴いて、上限、範囲、式を決め直す。
- 聴いた結果、この表の値は使わなくなった。入・切もやめ、強さのスライダーにした。いまの値は TICKET-005 と仕様書 4.3 にある。

## 音を出すときの安全(この段階での変更点)

この段階で、はじめて「音を大きくする」処理(イコライザーの増幅、ラウドネス)が入る。`CLAUDE.md` の決まりに従い、次を守る。

- リミッターを、増幅する機能より先に入れる(TICKET-001)。出力は、どんな場合も元の信号の上限(フルスケール)を超えない。
- 音量の倍率の上限(1.0)は変えない。
- 起動時には、保存したイコライザーの設定で加工が始まる。イコライザーで増幅していると、
  同じ音量の数値でも、段階2 より音が大きく出る(最大で +10 dB。リミッターの上限までは)。
  これは「起動時に音量が上がる変更」にあたるので、ここに書いて確認を受ける。
  - `state.json` が読めないとき、値が範囲の外のときは、イコライザーはすべて 0 dB、ラウドネスは切で始める。
  - 加工が始まる瞬間は、段階2 と同じく、倍率を 0 からなめらかに上げる。
- エンジンが加工を断った回は、イコライザーなしの音(音量とリミッターだけ)を出す。無音にも最大音量にもしない。
- 音を試す直前には、毎回、スピーカー側(SONOS Ray)の音量を下げてもらう。
