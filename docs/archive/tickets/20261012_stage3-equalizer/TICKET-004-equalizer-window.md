### イコライザーのウィンドウ(仕様書 5.2 のうち、この段階で作るもの)

- 縦のスライダー 10 本。下に、周波数と、いまの値(dB)。
- イコライザーの入・切(ポップアップのものと連動する)。
- 「フラットに戻す」。
- リミッターが働いていることの表示(一覧の README の「2 の補足」)。
  働いている間だけ、「音量が大きいため、音を抑えています」のような短い文を出す。
- プリセットの選択、「保存」「別名で保存」「名前の変更」「削除」「書き出し」「読み込み」は、段階4 で足す。
- 矢印キーでの操作は TICKET-006。

### 動き

- エンジンは、加工を始めるたびに作り直され、すべて 0 dB で始まる(TICKET-003)。
  加工を始めるとき(起動、「音声の加工」を入れ直したとき)に、いまの設定を、音を出し始める前にエンジンへ渡す。

- スライダーを動かしている間も、すぐに音へ反映する。値は 0.5 dB 刻み。
- イコライザーを切にしたときは、音がとぎれないこと。切り替え方は2つ考えられるので、聴いて選ぶ。
  - エンジンの部品を素通しにする。
  - 10 バンドの値を、一時的にすべて 0 dB にする(画面の値は残す)。
- 保存は、音量と同じく、変更の 0.5 秒後にまとめて行う。
- ウィンドウは1つだけ。開いているときにもう一度「イコライザーを開く…」を選ぶと、手前に出す。
  ウィンドウを閉じても、アプリは終了しない。
- ウィンドウを開いている間だけ、表示を更新する(リミッターの表示など。`docs/TODO.md` の申し送り)。

### 確かめること(試作からの申し送り)

- スライダーを連続して動かしたときに、エンジンが加工を断る回があるか。
  回数をウィンドウの隅に小さく出して確かめる(確認が済んだら消す)。
  断る回があって音に影響するときは、手を止めて、扱いを相談する。

### 安全のための決まり

- 起動時に、保存したイコライザーの設定で加工が始まる。増幅していると、同じ音量の数値でも段階2 より大きく出る
  (一覧の README の「音を出すときの安全」)。リミッターの上限は超えない。
- `state.json` が読めないときは、すべて 0 dB で始まる(TICKET-002)。

### 作ったもの

- ポップアップに、「イコライザー」の入・切(スイッチ)と、「イコライザーを開く…」を足した。
- イコライザーのウィンドウ(`SimpleEqualizer/EqualizerWindow.swift`)。縦のスライダー 10 本、周波数と値の表示、
  入・切、「フラットに戻す」、リミッターが働いているときの説明。
  確認用の「イコライザーを通せなかった回数」は、確認のあと消した。
- 値を変えると、すぐにエンジンへ伝え、0.5 秒後にまとめて保存する。起動時と、加工を入れ直したときは、
  音を出し始める前に、いまの値をエンジンへ渡す。

### 決めたこと

- **縦のスライダーは自分で作った。** macOS の標準のスライダーには、縦のものがない。
- **スライダーは、つまみを引いた長さのぶんだけ動く。押した場所へ値を飛ばさない。**
  標準のスライダーは、押した場所へ値が飛ぶ。イコライザーでは、ウィンドウを手前に出そうとして押しただけで、
  急に +10 dB になるおそれがあるので、やめた(`/code-review` の指摘)。
- **イコライザーを切にしたときは、10 バンドの値を 0 dB として設定する**(画面の値は残す)。
  もう1つの案(部品を素通しにする)は試していない。切り替えの瞬間の音は、利用者の確認で確かめる。
- **リミッターの表示は、最後に抑えたときから 2 秒保つ。** 保たないと、音の山に合わせて点滅して読めない。
- ウィンドウは、起動時には開かない。閉じても、アプリは終了しない。
- ウィンドウの見た目(スライダーの形、並び)は、Claude には見えないので、利用者の確認で直す前提である。
