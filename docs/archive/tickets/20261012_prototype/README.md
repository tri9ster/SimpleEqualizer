# 試作 チケット一覧(2026-10-12)

仕様書 11章の段階1にあたる。タップで取り出した音を、音量を変えて光デジタル出力へ流すだけのものを作り、
案A(Core Audio のプロセスタップ)で進めてよいかを判断する。

## この試作で答えを出すこと

1. 案A の API が、macOS 27 と USB SPDIF Adapter の組み合わせで動くか(仕様書 3.3)。
2. 音の遅れが、動画の視聴で気にならない範囲に収まるか(仕様書 3.3)。
3. 取り出した音を `AVAudioEngine` に通せるか(仕様書 7章の構成が成り立つか)。
4. 案A のまま段階2へ進むか、案B に切り替えるか。

そのほかの確認項目は `../../../research/Prototype_PreCheck.md` の3章にある。TICKET-003 で1件ずつ確かめる。

## 範囲に入れないもの

- イコライザー、ラウドネス、リミッター、プリセット、音量キー、状態の保存、メニューバー常駐(段階2以降)。
- SONOS のネットワーク操作(案C)の確認。仕様書 3.3 に残っているが、第2段階の候補なので、この試作では確かめない。
- 自動テスト。試作は「テストを先に書く」の対象外(`CLAUDE.md`)。

## 試作のコードの扱い

- Xcode のプロジェクト、アプリの識別子(Bundle ID)、署名の設定は、そのまま本番に引き継ぐ。
  変えると macOS の許可を出し直すことになるため。
- 音声を扱うコードは、動くことを確かめるためのもの。段階2で作り直してよい。捨てたコードも記録に残す。

## 作業順序

```
(利用者) Xcode の初回セットアップ
    └─ TICKET-001 プロジェクトの作成
           └─ TICKET-002 音の取り出しと出力
                  └─ TICKET-003 実機での確認
                         └─ TICKET-004 AVAudioEngine に通せるかの確認
                                └─ TICKET-005 まとめと判断
```

- TICKET-001 を先にする理由: 許可が `.app` と署名にひもづくので、音を扱う前に器を決める必要がある。
- TICKET-003 を TICKET-004 の前にする理由: いちばん単純な経路で案A が動くかを先に確かめる。
  動かなければ TICKET-004 は行わず、TICKET-005 で案B への切り替えを検討する。
