## 概要

MIT の LICENSE を置き、配布して問題がないか(名前、アイコン、Apple の部品)を確かめる。

## 現状

2026-10-18 時点。未着手。

- 外部のライブラリは使っていない(Apple 標準のフレームワークだけ)。
- LICENSE には、著作権を持つ人の名前を書く。どの名前(本名、GitHub のアカウント名など)で書くかは決まっていない。
- 音量の表示と警告の印に、Apple のアイコン集(SF Symbols)を使っている。

## 対応方針・作業手順

1. 利用者に、LICENSE に書く名前を決めてもらう(Claude は、名前を推測して書かない)。
2. `LICENSE`(MIT の標準の文面)を置く。
3. 調べて、結果を報告する:
   - 「SimpleEqualizer」と同じ、またはまぎらわしい名前の製品(とくに macOS のアプリ)がないか。商標の登録があるか。
   - SF Symbols を、配布するアプリの中で使う条件(Apple の利用許諾)。
   - アイコンの元データ(`design/`)の出どころ(利用者に確かめる)。
4. 問題があれば、対処の案を出して、利用者に決めてもらう(名前を変える場合は、アプリの識別子を変えないで済むかも調べる)。

## 実施結果

2026-10-18 に行った。

### 決めたこと(利用者)

- LICENSE の著作者は、GitHub のアカウント名にする(`gh` で読んだ名前を、そのまま書いた)。
- アイコンの元データ(`design/`)は、利用者が自分で作ったもの。

### 作ったもの

- `LICENSE`: MIT の標準の文面。年は 2026。
- `README.md` の最後に、利用許諾の節を足した(英語の README は TICKET-007 で作る)。

### 調べた結果

| 対象 | 結果 | 扱い |
| --- | --- | --- |
| 外部のライブラリ | 使っていない(Apple 標準のフレームワークだけ) | 守るべき条件はない |
| アプリの名前「SimpleEqualizer」 | 同じ名前の製品(App Store のアプリなど)と、商標は、ウェブの検索では見つからなかった。GitHub には、同じ名前の小さなリポジトリが 10 件ほどある(Android、JUCE のプラグイン、Chrome の拡張など。どれも個人の作品) | 変えない。説明的な、ありふれた名前なので、ぶつかって困ることはない見込み。ただし、商標の正式な調べ(特許庁などのデータベース)はしていない |
| SF Symbols | 音量の表示(スピーカーの印)と、メニューバーの警告の印で使っている。Apple の説明では、SF Symbols は Xcode と SDK の利用許諾にしたがう、システムの画像として扱われ、アプリの画面の中で使える。アプリのアイコンやロゴに使うことは認められていない | 問題なし。アプリのアイコンとメニューバーのふだんのアイコンは、利用者が作ったもの(`design/`)で、SF Symbols ではない |
| アイコンの元データ | 利用者が自分で作った | 問題なし。MIT でいっしょに配る |
| 機材やソフトの名前(macOS、SONOS など) | README と画面には、機材の名前を書かない決まり。macOS など、動く環境を示すための名前は、説明として使ってよい範囲 | 問題なし |

- SF Symbols の条件は、Apple の開発者フォーラムなどに引用された説明で確かめた。Apple の利用許諾の原文は読んでいない。
