# TICKET-005: 画面の英語対応

## 概要

画面の文言を、日本語と英語の両方で用意する。macOS の言語の設定に合わせて切り替える。

- 画面の文言は、すべて日本語で、コードの中に直接書いてある(ポップアップ、イコライザーのウィンドウ、設定のウィンドウ、確かめる画面、許可の説明文)。
- `Core/` にも、画面に出す文言がある(扱えない出力先の理由など)。
- 許可の説明文(`Config/Info.plist` の `NSAudioCaptureUsageDescription`)も日本語。

## 対応方針・作業手順

1. Xcode の文字列カタログ(`Localizable.xcstrings`)を使う。開発の言語を日本語のままにするか、英語にするかを、作りやすさから決めて報告する。
2. アプリと `Core/` の文言を、カタログに移す。`Core/` の文言は、パッケージの中のカタログに置く。
3. 英語の訳を作る。利用者に、英語の文言の一覧を見せて、確かめてもらう。
4. 許可の説明文(`InfoPlist.xcstrings`)も、両方の言語にする。
5. 文言を、カタログから読んでいるかの自動テストを、`Core/` の分について足す(テストを先に書く)。
6. 英語に切り替えて、画面を確かめてもらう(長い英語で、ボタンや説明がはみ出さないか)。

## 影響ファイル

- `SimpleEqualizer/` の画面のファイル全部、`Core/Sources/SimpleEqualizerCore/` の文言を持つファイル、`Config/Info.plist`、文字列カタログ(新規)

## 実施結果

2026-10-26 に作った。2026-11-08 に、利用者が確かめ終えた(完了)。

- 元の文言は、日本語のままにした(利用者の判断)。日本語でも英語でもない言語の Mac では、英語で出す(利用者の判断)。
- 作り方と理由は `architecture.md` の「6. 画面の言語」。つまずいたことは `failures.md` の 2026-10-26。
- 手順 5(`Core/` の分の自動テスト)は、テストを先に書き、失敗を確かめてから作った。アプリのカタログの抜けも、同じテストで確かめる。
- 手順にはなかったが、行ったこと:
  - 「フラット」の名前を言語で変えたので、どの言語の「フラット」の名前もプリセットに使えなくした(言語を切り替えたときに名前が重ならないように)。
  - カタログの見出しをコードに合わせるスクリプト(`tools/sync-strings.sh`)を足した。
  - 設定のウィンドウで、画面の言語(システムの設定に合わせる、日本語、English)を選べるようにした(2026-10-27、利用者の指示)。
  - 音量キーを押したときの表示の消音を、ボタンの名前と分け、「消音中」(英語は「Muted」)にした(2026-11-07、利用者の指示)。
- 英語の文言の中身、英語の macOS での画面、日本語の画面は、利用者が確かめた(2026-11-08)。
