## 対応方針・作業手順

2. 利用者の確認を受けてから、リポジトリを作って置く(外に出る操作なので、毎回確かめる)。

### 公開の直前の点検(2026-11-15、Claude。手順1)

Git に入っている 178 件(TICKET-001 のときより、`site/`、`assets/` などで 38 件多い)を、TICKET-001 と同じ項目で調べた。値そのものは書かない。

| 調べたこと | 結果 |
| --- | --- |
| 名前、メールアドレス、利用者固有の絶対パス | 入っていない |
| チームの番号、開発用の証明書の名前、前に使っていた識別子 | 入っていない。識別子は公開してよい値。署名の設定は見本だけ |
| 認証情報 | 入っていない |

出てはいけない情報は、見つからなかった。

### 公開するときの注意(2026-11-15、Claude)

- いまのリポジトリで履歴を消して force push しても、PR #1〜#4 の中の古いコミットは GitHub に残る
  (PR の参照は、利用者には消せない)。いまのリポジトリをそのまま public にすると、PR の画面から古いコミットが見える。
  新しいリポジトリを作り、履歴のない1つのコミットで公開するほうが確実。
- 公開と同時に行うこと: README(英語と日本語)からホームページへのリンク、About の Website(ホームページの TICKET-004)、
  Pages を有効にする(ホームページの TICKET-005)、`CLAUDE.md` の「Git と GitHub」を、公開したあとの状態に直す。

### 公開のやり方(2026-11-15、利用者が決めた)

- 利用者が、いまのリポジトリの名前を `SimpleEqualizer_dev` に変え(非公開のまま)、同じ名前 `SimpleEqualizer` で公開のリポジトリを作った。
  ページのダウンロードのボタンが `tri9ster/SimpleEqualizer` を指しているので、名前を変えない。
  新しいリポジトリには、GitHub が作った LICENSE のコミットが1つある。中身は手元の `LICENSE` と同じ。
- 手元では、リモートの名前を `origin` から `dev` に変え、アドレスを `SimpleEqualizer_dev` に直した
  (`origin` のアドレスが新しい公開のリポジトリを指したままだったため。そのまま push すると、開発の履歴が公開される)。
- 公開する中身の仕上げ: README のリンク(ホームページの TICKET-004)と、`CLAUDE.md` の「Git と GitHub」を、このブランチで直した。

### 公開とリリース(2026-11-15)

- 公開のリポジトリの履歴は、GitHub が作った LICENSE のコミットと、その上に積んだ公開のコミットの2つ(利用者が選んだ。force push を避けるため)。
  公開のコミットの中身は、非公開のリポジトリの `main`(PR #5 をマージしたあと)と同じ 178 件。`private/` と署名の設定は入っていない。
- 手元では、古い `main` を `dev-main` に改名して残し、公開のコミットを新しい `main` にした(`origin` を追う)。
- 利用者が、ログインしていない状態で、リポジトリ、ページ、About を確かめた。
- タグ `v0.1` を公開のコミットに付け、リリース「SimpleEqualizer 0.1」に `SimpleEqualizer-0.1.dmg` を置いた。
  説明は英語と日本語で、開く前に音量を下げること、公証を受けていないので止められることと開き方、dmg の SHA-256 を書いた。
- Claude が、ログインしないでリリースから dmg を落とし、SHA-256 が手元のものと一致することを確かめた。
  利用者が、ページのダウンロードのボタンからリリースへ行けること、落とした dmg が開けることを確かめた。
