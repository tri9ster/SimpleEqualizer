# TICKET-006: 署名の方式と、配布物の作り方

## 概要

Apple Developer Program に登録しない前提で、ビルド済みのアプリの署名の方式と、配布物(zip など)の作り方を決める。

## 依存関係

## 現状

2026-10-18 時点。未着手。

- いまは、開発用の証明書で署名している。この証明書は、配布用ではない。
- 登録しないので、Developer ID の署名と、Apple の公証は受けられない。ほかの人の Mac では、開くときに警告が出る。
- macOS の許可(システム音声の録音、アクセシビリティ)は、アプリの署名と結びついている。
  署名の方式によっては、新しい版に入れ替えるたびに、許可を出し直すことになる。

## 対応方針・作業手順

1. 調べて、結果を `docs/research/` に書く:
   - その場かぎりの署名(ad-hoc)と、開発用の証明書で署名した場合の、それぞれで:
     ほかの Mac での開き方(警告の内容、システム設定の「このまま開く」)、版を上げたときに許可が残るか、ログイン時の起動が動くか。
   - ダウンロードしたファイルにつく、「インターネットから来た」印(quarantine)の扱い。
   - 配布物の形(zip か dmg か)。
2. 案を出して、利用者に決めてもらう。
3. 配布物を作る手順を、`tools/` のスクリプトにする(Release でビルドし、署名を確かめ、zip にする)。
4. 自分の Mac で、配布物を開けることを確かめる。できれば、別の Mac かユーザーで確かめる。

## 実施結果

### 調べた結果(2026-10-18)

`docs/research/Distribution_Signing.md` に書いた。要点:

- いまのアプリの識別子に、利用者の名前が入っている。開発用の証明書の名前には、メールアドレスが入っている。
  どちらも、ビルド済みのアプリを受け取った人なら読める。このままでは配れない。
- ad-hoc の署名では、版を上げるたびに許可が外れる。自己署名の証明書なら、残るという報告がある。
- 署名の設定がない状態では、識別子が空になる(ソースからビルドする人が困る)。

### 利用者が決めたこと(2026-10-18)

- 署名の方式: 自己署名の証明書。
- アプリの識別子: 公開してよい値(GitHub のアカウント名を使う形)に変える。
- 配布物の形: dmg。

### 作ったもの

- `Config/Project.xcconfig` に、公開してよい識別子と、署名の初期値(その場かぎりの署名)を書いた。
  前の識別子は、利用者の `Config/Signing.xcconfig`(Git 管理外)から外した。
- `Config/Signing.xcconfig.example` を、識別子を持たない形にし、配布物用の証明書の名前(`RELEASE_SIGN_IDENTITY`)の書き方を足した。
- `tools/make-release.sh`: Release でビルドし、写したアプリを自己署名の証明書で署名し直し、dmg にまとめる。写したアプリは消す。
- `CLAUDE.md`: 識別子を一度だけ変えたこと、配布物を開発用の証明書で署名しないことを書いた。

### 確かめたこと

- 新しい識別子で、Debug のビルドが通った。
- スクリプトは、証明書の名前がないときに、説明を出して止まる。
- 自己署名の証明書は、利用者がキーチェーンで作った(名前は個人の情報を含まない、有効期間 10 年、コード署名にだけ信頼)。
  中身を読んで、メールアドレスなどが入っていないことを確かめた。
- 配布物の署名と中身に、個人の情報が入っていないことを確かめた。

### 利用者が試したこと(2026-10-18)

`research/Distribution_Signing.md` の4章。

- 試験 1(はじめて開く): 止められたあと、「プライバシーとセキュリティ」の「このまま開く」で開けた。
  アクセシビリティは一覧に出ず、「+」で足した。足したあと、音量キーが効いた。
- 試験 2(ビルド番号を上げた版に入れ替える): また「このまま開く」が要った。許可は出し直さずに、音の加工も音量キーも効いた。
  許可を求める画面は出なかった。

### 開き方の案内(利用者が決めた)

- README(TICKET-007)と、dmg の中の案内のファイルの両方に書く。dmg の案内は `tools/dmg-guide.txt` に書き、スクリプトで dmg に入れる。

### 残したこと

- アクセシビリティの一覧に出なかった理由は分かっていない。TICKET-008 で、`/Applications` に置いて切り分ける。
- デスクトップの試験用フォルダ(`SimpleEqualizer-test`)は、利用者が片付ける。

### `/code-review` の指摘と対処

| 指摘 | 対処 |
| --- | --- |
| `Signing.xcconfig` に古い識別子(個人の情報を含む)が残っていると、気づかずに配布物に入る | スクリプトで、ビルドの設定と署名したアプリの識別子を、`Project.xcconfig` の値と比べて、違えば止める。古い識別子を足して、止まることを確かめた |
| 途中で失敗すると、写したアプリが残り、macOS に余分に登録される | `trap` で、失敗しても消して登録を外す |
| 見本の設定ファイルをそのまま写すと、ビルドできない | 開発用の証明書の行も、コメントにした |
| README が、署名の設定を必須と書いている | なくても作れること、その場合は作り直すたびに許可が外れることを書いた |
| 証明書の確かめ方が、途中で止まる書き方で、同じ名前の証明書が2つあるときも通る | 一覧を変数に入れてから数え、使える証明書(`-v`)が1つのときだけ進む |
| 証明書の名前の読み方が、空白やコメントに弱い | 前後の空白、行の終わりのコメント、改行の違いを除いて読む |
| 版の番号や生成物の場所が読めないとき、気づかない | 空なら止める。エラーの出力を捨てない |
| 案内に、証明書の期限のことが書かれていない | 証明書は 10 年。作り直さない決まりを `CLAUDE.md` と調査の資料に書いた |
| 識別子を変える前の、ログイン項目や許可の残りの片付け方がない | TICKET-008 の手順に足した |
| スクリプトが `DerivedData` の外へアプリを写す(`CLAUDE.md` の決まり) | 例外として `CLAUDE.md` に書いた。終わったら必ず消して登録を外す |

- 見直しのあとの試験で、直す前のスクリプトが、試験用の仮の識別子のまま dmg を作ってしまった(ファイルの書き込みが失敗していたのに気づかず試した)。
  作り直して、正しい識別子になったことを確かめた。仮の識別子のアプリは、macOS に登録されていなかった。
