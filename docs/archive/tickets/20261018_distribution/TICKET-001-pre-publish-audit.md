# TICKET-001: 公開前の点検(Git の履歴と docs)

## 概要

## 対応方針・作業手順

1. 調べる(Claude。書き換えはしない):
   - すべてのコミットの作者と、コミットした人の名前とメールアドレス。
   - 履歴の全部から、個人情報、利用者固有の絶対パス、署名の識別子(チームの番号、証明書の名前、アプリの識別子)、認証情報を探す。
   - `docs/`、`input/`、`design/` の中で、公開に向かない書き方を拾う。
2. 結果を報告し、利用者に選んでもらう。案は次のとおり。
   - 案1: 履歴をそのまま公開する(作者のアドレスが出る)。
   - 案2: 履歴の作者を、GitHub が用意する、公開用のアドレス(noreply)に書き換えてから公開する。
   - 案3: 履歴を持たない、新しいリポジトリとして公開する(手元の履歴は、手元にだけ残す)。
3. 決まった方法で直す。履歴の書き換えは元に戻せないので、先に手元の写しを作ってから行う。
4. これからのコミットで使う作者のアドレスを、公開用のものにするかも決める(`git config` の設定は、利用者が行う)。

### 調べた結果(2026-10-18、Claude)

いま Git に入っているファイルを調べた。

| 調べたこと | 結果 |
| --- | --- |
| アプリの識別子、チームの番号(`Config/Signing.xcconfig` の値) | どのファイルにも入っていない |
| 証明書の名前 | 一般的な名前(`Apple Development`)だけで、個人を示すものはない |
| 名前、メールアドレス、利用者固有の絶対パス、ホスト名、アカウント名 | 入っていない |
| 装置の識別子(シリアル番号を含むことがある UID)、IP アドレス、MAC アドレス | 入っていない(テストの中の、作りものの UUID だけ) |
| 画像(`design/` の SVG、アイコンの PNG)に埋め込まれた、作った人やパスの情報 | 入っていない |
| 画面の文言と `README.md` の機材の名前 | 入っていない |

公開する前に、扱いを決めたほうがよいもの(どれも個人情報ではない):

| 対象 | 内容 | 案 |
| --- | --- | --- |
| `docs/` の機材の名前 | SONOS Ray、Mac mini、ディスプレイの型番などが、約 30 のファイルにある | 残す。何で確かめたかが分かり、開発の記録として役に立つ |
| 開発の環境のこと | 外付けドライブの容量(`TODO.md`)、外付けドライブで開発していること(`dev-log.md` など) | 容量の行は消す。外付けで開発していることは、設計の理由になっている箇所があるので残す |
| 利用者の家庭用のリポジトリの話 | `dev-log.md` の1節と、`research/Superpowers_Comparison.md` | `dev-log.md` は「別のリポジトリ」と書き直す。`Superpowers_Comparison.md` は、アプリではなく開発の道具の話なので、公開するものから外す |
| `CLAUDE.md` | Claude に向けた開発の決まり | 残す。Claude Code で開発したことが分かり、ほかの人が手を入れるときにも使える |
| `input/` | `README.md` と配布の方針は Git に入る。利用者のメモ(`memo.md`)は入っていない | このまま(メモは公開しない) |
